# 策略中心模块

## 定位

`strategy_center` 是短线策略研究、候选事实和模拟交易的审计边界。它不调用 Provider、不连接券商、不自动下单，也不会把尚未经过 evaluator 和回测验证的配置伪装成可执行策略。

当前阶段只实现策略定义与结果承载层：用户可以创建研究草稿，每个策略自动拥有一个动态策略股票池；候选和模拟交易表已经预留完整生命周期，但没有任何代码会自行生成候选、确认买点或创建模拟成交。

## 数据模型与状态

| 表 | 层 | 作用 |
| --- | --- | --- |
| `t_strategy_definition` | Business | 策略代码、研究状态、确认时点、最长持有交易日、规则/风险配置 JSON 与专属策略池关联。 |
| `t_strategy_candidate` | Derived / 审计 | T 日收盘候选和 T+1 确认结果；唯一键为 `strategy_id + signal_trade_date + stock_code`。 |
| `t_strategy_paper_trade` | Business / 审计 | 仅当候选实际触发买点后创建的一笔模拟交易；唯一关联一个候选。 |

候选状态按以下含义预留：

- `pending_confirmation` / `watching`：T 日候选，等待次日集合竞价、开盘或盘中确认。
- `entry_triggered`：确认条件满足，才允许创建一笔 `t_strategy_paper_trade`。
- `not_triggered`：确认窗口结束仍没有买点；**不产生交易，不计为策略盈亏或胜率失败**。
- `expired` / `cancelled`：候选过期或被明确取消。

模拟交易状态为 `open`、`closed` 或 `void`。其 `entry_evidence`、`exit_evidence` 和 `risk_plan` 用来在真正触发时保存 Quote、五档、分钟线特征和策略风险计划；不保存全市场高频盘口。

每个策略创建时会生成一个 `t_stock_pool`：`pool_type='strategy'`、`is_dynamic=true`、`dynamic_rule='strategy_candidates'`。该池只展示仍处于 `pending_confirmation/watching` 的候选；它不允许手工加减成员，之后成交、未触发或过期都会由 evaluator 的状态更新自然退出。策略改名会同步更新该池名称；归档策略会停用该池并从动态成员视图移出，恢复为草稿或研究状态才重新展示。虽然它由系统维护以防止混入手工成员，股票池目录仍按 `pool_type='strategy'` 展示为“策略池”，不是普通系统池。创建时实时策略默认为关闭，不会占用 TickFlow Quote、五档或 MooTDX 分钟线资源。

## API

| API | 说明 |
| --- | --- |
| `GET /api/v1/strategies/dashboard` | 返回策略定义、候选/模拟交易状态计数和执行器就绪状态。 |
| `POST /api/v1/strategies` | 创建短线策略草稿与专属动态策略池。请求包括 `strategy_code`、`strategy_name`、`entry_mode`、`max_holding_trade_days`、可选说明和 JSON 配置。 |
| `PATCH /api/v1/strategies/{strategy_code}` | 更新草稿/研究配置或归档状态。当前传入 `status=enabled` 会返回 `strategy_evaluator_not_available`，防止没有执行器时误启用。 |
| `GET /api/v1/strategies/candidates` | 只读候选和已关联模拟交易；可选 `strategy_code`、`signal_trade_date`，`limit` 默认 200、范围 1–1000。 |

前端路径为 `/strategies`。页面将“未触发买点”和“模拟成交”分开统计，并明确提示当前没有 evaluator；它不会从页面写候选或调用行情源。

## 迁移与当前边界

先由表 owner 执行：

```sql
\i /root/sql/69-strategy-research-foundation.sql
```

随后部署/重启后端和刷新前端。脚本只新增三张表、索引和约束，不创建策略、不改写已有股票池成员，也不执行交易或调度任务。

下一阶段才会实现：基于已完成盘后事实的具体 evaluator、T+1 的 TickFlow/MooTDX 确认、触发时模拟成交/通知、T+1 及以后持有和卖出规则、以及以“已成交交易”为样本的回测统计。策略在这些规则经历史验证并由用户确认前保持草稿或研究状态。
