# 数据源与入库矩阵
<!-- wiki-migration -->

## 使用原则

- Tushare 是日频事实主源，适合批量沉淀。
- MooTDX 是实时 quote、分钟、分笔、盘口主源。
- AkShare 是板块、指数、公告、实时排行等 fallback 和补充源。
- Skill 只用于问财、妙想、Kimi 搜索类补充，不作为核心行情事实主源。
- Raw 层可以多源共存，canonical 分析事实不按 source 重复造多份。
- 业务服务只消费统一 Canonical 字段，不直接消费 Tushare、AkShare、MooTDX 或 Skill 原始字段。字段命名、单位和日期入参规范见 [[量化字段标准化与初始化沉淀规划]]。

## 实时性口径

| 口径 | 含义 | 典型数据 | 处理方式 |
| --- | --- | --- | --- |
| 实时 | 盘中刚从 MooTDX 等实时源获取，适合秒级/十秒级展示 | quote、盘口、当日分时、分笔 | 进入内存缓存和页面推送，默认不高频入库。 |
| 准实时 | 来自 AkShare/东财等排行接口，可能有分钟级延迟 | 板块资金排行、热门排行 | 页面轮询或实时服务缓存，必要时低频审计。 |
| 盘后 | 交易结束后由 Tushare/调度沉淀的最终事实 | 日线、daily_basic、资金流、龙虎榜、板块日线 | 写 canonical 表，用于因子、选股、回测。 |
| 历史 | 已沉淀或回填的历史数据 | 历史分钟线、历史日 K、历史因子 | 只读数据库，不触发实时 Provider。 |

规划细节见 [[实时数据能力规划]]。

## Skill 数据边界

| Skill family | 适用场景 | 是否入库 | 说明 |
| --- | --- | --- | --- |
| 问财 | 选股语义查询、事件查询、专题补充 | 视业务而定 | 不能作为核心行情事实主源。 |
| 妙想 | 金融资讯、宏观、主题研究、诊断 | 视业务而定 | 适合生成分析上下文或补充事件。 |
| Kimi Search | Web 搜索、新闻补充 | 默认不入库 | 后续可作为 AI 复盘上下文来源。 |

Skill 的“实时”表示调用当下返回最新搜索结果，不等于交易所行情实时。价格、盘口、分时、分钟资金流和板块资金排行不能把 Skill 作为主源；Skill 更适合在行情异动发生后补新闻、公告、题材解释和语义查询。

## 当前优先补齐

1. `t_index_basic/t_index_component`：已新增 `sync_index_catalog` 同步任务，下一步执行任务并验证核心指数和成分覆盖。
2. 数据资产巡检：为每类数据建立最新日期、行数、缺口和任务健康度。
3. 财务同步链路：Tushare 财务接口已经登记，下一步需要入库和页面。
4. 公告/事件链路：公告数据当前很少，需要形成搜索和个股事件展示。
5. 量化字段标准化：统一 `stock_code/trade_date/start_date/end_date` 入参、金额/成交量/百分比单位、Provider Adapter 映射和结构化日志。
6. 指标字段字典：将系统自算、Tushare 专业因子、资金因子、板块因子统一登记，供选股和回测使用。
7. 历史初始化回填：新增部署后一次性 backfill 任务，补齐日 K、daily_basic、资金流、指数、板块历史数据；每日任务只做增量。
8. 实时数据底座：新增 `RealtimeMarketService`，统一 MooTDX 实时 quote/分钟/盘口、AkShare/东财准实时排行、SSE/WebSocket 推送和监控触发。
