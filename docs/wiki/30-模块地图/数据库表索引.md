## 三层数据

| 层 | 表 | 说明 |
| --- | --- | --- |
| Raw | `t_provider_raw_record`、`t_canonical_source_conflict_backup` | 保存外部源原始响应，以及 canonical 单事实收口时被归并的旧多源行快照。 |
| Canonical | `t_stock`、`t_trade_calendar`、`t_daily_bar`、`t_minute_bar`、`t_tick_trade` | 股票基础资料和核心行情事实；`t_stock.is_st` 由每周基础资料同步自动维护，作为实时情绪/策略排除条件。`t_minute_bar` 按交易日分区，迁移前资产保留在 `t_minute_bar_legacy`。`t_quote_snapshot` 历史表保留但已废弃为 EOD canonical 事实。 |
| Canonical | `t_sector_basic`、`t_sector_component`、`t_sector_bar`、`t_index_basic`、`t_index_component`、`t_index_bar` | 板块/概念/行业、指数和成分股事实；`t_sector_component` 与 `t_index_component` 都保存当前有效关联。 |
| Canonical | `t_stock_fund_flow_daily`、`t_sector_fund_flow_daily`、`t_lhb_event`、`t_lhb_seat_detail`、`t_stock_north_hold_daily`、`t_announcement` | 个股/板块资金流、龙虎榜、公告事件事实；`t_stock_north_hold_daily` 保留为历史/实验表，默认不再由每日收盘任务沉淀。 |
| Canonical | `t_stock_daily_basic`、`t_stock_adjust_factor`、`t_stock_technical_factor_daily`、`t_stock_chip_perf_daily` | Tushare 日度估值、流动性、复权和专业技术因子事实；`t_stock_chip_perf_daily` 仅保留历史/实验筹码胜率摘要，不再作为每日全市场批量沉淀表，`cyq_chips` 明细不再作为业务沉淀表。 |
| Canonical | `t_financial_statement`、`t_financial_indicator`、`t_corporate_action` | 三大报表、财务指标、分红与公司行动。 |
| Canonical | `t_margin_summary_daily`、`t_margin_detail_daily`、`t_limit_event_daily`、`t_stock_holder_count`、`t_stock_top_holder`、`t_market_daily_stat`、`t_index_daily_basic` | 融资融券、涨跌停、股东专题、市场交易统计和指数每日指标事实。 |
| Derived | `t_stock_factor_daily`、`t_stock_factor_minute`、`t_sector_factor_daily`、`t_index_factor_daily`、`t_technical_indicator_snapshot`、`t_factor_definition` | 个股/板块/指数因子与技术快照；`t_stock_factor_daily` 包含 MA5/10/20/30/60，`t_stock_factor_minute` 由 15:30 分钟任务按股票分片集合计算并持久化，两个分钟表都按交易日分区。 |
| Config | `t_system_config`、`t_config_value`、`t_config_option`、`t_runtime_call_log` | Search、LLM、Notification、Market Data 的固定配置对象、Key/Token 池和参数。 |
| Scheduler | `t_scheduler_job`、`t_scheduler_job_run`、`t_scheduler_tag`、`t_scheduler_job_tag` | 调度任务定义和运行日志，以及可扩展的任务标签和多对多归类；包含收盘数据沉淀、板块同步和股票基础资料同步任务定义。 |
| Business | `t_stock_pool`、`t_stock_pool_member` | 股票池定义与成员关联；`all_a_share` 为沪深 `t_stock.status=active` 动态范围，不保存成员关系，北交所/BSE 当前标记为 `excluded`。 |
| Business | `t_market_universe`、`t_market_universe_member` | 第三方标的池目录与成员有效期历史。当前用于 TickFlow 的原始池、SW1/SW2/SW3 行业辅助层；不替代 Tushare 概念或用户股票池。 |

数据资产巡检索引：

```text
docs/sql/37-data-assets-inspection-indexes.sql
```

`37` 不修改事实表结构和数据，只为数据中心读取最新交易日和快照时间补充前导索引。它包含 `t_minute_bar/t_stock_factor_minute` 分区表的 `trade_date` 前导索引；这些分区表如果未 ANALYZE，`pg_class.reltuples` 可能显示 0，但实际数据仍存在，数据中心会结合最新日期股票数和非空分区估算行数。主数据表如 `t_stock/t_sector_basic/t_sector_component` 不要求按 `updated_at/created_at` 建巡检索引，数据中心只展示它们的业务计数和关系覆盖。

数据资产覆盖率性能索引：

```text
docs/sql/62-data-assets-cache-performance-indexes.sql
```

`62` 由对应事实表 owner 在非事务会话执行。它为 `t_daily_bar/t_stock_daily_basic/t_stock_fund_flow_daily/t_stock_technical_factor_daily/t_stock_factor_daily` 增加 `trade_date + stock_code` 前导索引，并补 `t_limit_event_daily(trade_date, event_type, stock_code)`；最后对相关表执行 `ANALYZE`。脚本不删除数据、不执行 `VACUUM FULL`；它只服务数据中心最新日期覆盖率和日频健康度聚合。

`58-daily-close-four-stage-pipeline.sql` 不改表结构或删除事实。它把 `t_minute_bar/t_stock_factor_minute` 的日常生产任务统一改为 `daily_close_minute_ingest`，两张表默认共同保留最近 30 个交易日；核心、增强和缺口修复任务不再重复生成分钟因子。

docs/sql/59-scheduler-job-tags-and-retire-obsolete-jobs.sql

技术快照回填任务：

```text
docs/sql/46-technical-snapshot-backfill-job.sql
```

`46` 只写入 `backfill_technical_snapshots` 调度任务定义，不改事实表结构。它按股票池和交易日区间读取 canonical 日线、分钟线与因子表，重算 `t_technical_indicator_snapshot`；默认 `append_safe`，必要时可用 `rebuild` 重建指定范围。

历史数据资产任务收敛与指数因子：

```text
docs/sql/55-data-asset-history-pipelines.sql
docs/sql/56-sector-history-range-backfill.sql
```

`55` 为 `t_stock_factor_daily` 增加 `ma30/ma60`，创建 `t_index_factor_daily`，并将历史任务定义收敛为个股/板块/指数各两段。它删除被替换的 7 条 `t_scheduler_job` 定义，但保留旧 `t_scheduler_job_run` 日志。当前任务与表依赖见 [[历史数据资产初始化]]；旧 `46` 的任务定义会被 `55` 替换，技术快照改由 `backfill_stock_daily_factors` 日频集合计算，不再重算历史分钟因子。

`56` 是可重复执行的 DML 修正脚本，只更新 `backfill_sector_daily_facts` 的定义：板块日 K 按板块代码一次请求完整日期区间，默认 12 个 worker；概念/行业资金流按已用真实接口逐日对账的 20 交易日窗口、独立 2 个 worker 执行。脚本不改事实表结构和历史运行日志，执行后需要 reload Scheduler。

股票退市名称状态修正：

```text
docs/sql/38-stock-basic-delisted-name-normalization.sql
```

`38` 可重复执行。它只修正 `t_stock.status` 和股票池成员关系，不删除历史行情事实。后端 `sync_stock_basic` 也会把名称以 `退市` 开头的沪深股票归为 `delisted`，避免 Tushare `list_status=L` 但展示名称已退市时重新进入 active universe。
