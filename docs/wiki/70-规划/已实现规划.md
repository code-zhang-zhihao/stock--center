## 当前主线

当前建设顺序仍是：

```text
量化字段标准化 -> 数据资产 -> 实时数据底座 -> 市场总览 -> 自选/股票池 -> 指标与选股 -> 回测 -> 监控 -> 专题分析 -> AI 与扩展数据
```

已完成的核心方向：

- 数据库统一使用 `t_` 前缀，保留 Raw / Canonical / Derived 三层思路。
- Canonical 分析事实采用单业务事实，不再按 `source` 制造多份事实；`source` 只记录最终来源。
- 股票关联键统一使用无后缀 `stock_code`。
- 北交所/BJ/BSE 统一为 `excluded`，不进入沪深 active universe；名称以 `退市` 开头的沪深股票归为 `delisted`，不进入每日沉淀范围。
- Tushare 作为日频事实主源，TickFlow 作为实时 Quote/五档主源，MooTDX 作为实时分钟线主源，AkShare 作为 fallback/准实时补充，Skill 不作为核心行情事实主源。`t_quote_snapshot(snapshot_kind='eod')` 已废弃，盘后价格事实只认 `t_daily_bar`。
- 历史事实和历史因子回填统一支持 `ingest_mode=append_safe|rebuild`：默认安全补缺，必要时目标范围重建。

## 历史因子是否可以回填

可以。历史任务已按个股、板块、指数三类资产收敛，每类保留事实和因子两段，不混入每日核心/增强/修复任务。

已实现任务：

```text
backfill_stock_daily_factors
backfill_sector_daily_factors
backfill_index_daily_factors
```

核心原则：

- 只读 canonical/derived 依赖表，不调用 Tushare、MooTDX、AkShare 或 Skill。
- 输入为 `start_date/end_date`、`pool_code`、`ingest_mode`、`max_stocks`、`factor_window_trade_days`、`sql_stock_chunk_size` 等运维参数。
- `backfill_stock_daily_factors` 先按 `t_trade_calendar` 展开交易日，再按连续交易日窗口由 PostgreSQL 窗口函数和 `INSERT ... SELECT` 计算；每个窗口按默认 200 只股票独立提交，并以相同方式生成日频技术快照。
- 股票日频因子依赖 `t_daily_bar`、`t_stock_fund_flow_daily`、可选 `t_stock_technical_factor_daily`。
- 历史初始化不生成分钟线和分钟因子；分钟资产只从项目运行后的每日/实时链路逐步积累。
- 历史技术快照由 `t_daily_bar + t_stock_factor_daily` 集合生成，不再依赖分钟事实或 `t_quote_snapshot(snapshot_kind='eod')`。
- 板块因子依赖 `t_sector_component/t_sector_bar/t_sector_fund_flow_daily/t_daily_bar/t_stock_fund_flow_daily/t_limit_event_daily`。
- 缺依赖时写 warning 和 result_summary，不触发外部补数。

当前代码状态：

- `IndicatorEngineService.calculate_market_close()` 已能按单日计算日频因子、分钟因子、技术快照。
- `IndicatorEngineService.calculate_sector_factors()` 已能按单日计算板块因子。
- `FactorBackfillService` 已补齐历史区间循环、PostgreSQL 集合计算、参数 schema、调度 handler 和 seed SQL。
- 历史任务收敛代码已通过后端单元测试和前端类型检查；`backfill_sector_daily_facts` 已完成单日、5 板块的真实调度 smoke。新数据库应依次执行 `docs/sql/55-data-asset-history-pipelines.sql`、`docs/sql/56-sector-history-range-backfill.sql`，再按 [[历史数据资产初始化]] 的最小参数逐项验证其余任务。
