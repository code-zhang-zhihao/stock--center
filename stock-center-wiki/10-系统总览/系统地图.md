# 系统地图

## 一句话理解

`stock-center` 采用新的 `python-back` 作为后端核心，第一阶段只迁移行情与数据引擎。旧 `stock-analysis` 是参考源，不再承载新架构实现。

## 分层

| 层 | 责任 |
| --- | --- |
| API | FastAPI 暴露 `/api/v1/market-data/query/*`。 |
| Query Service | `MarketDataQueryService` 统一 `query_mode`、`engine_priority`、fallback、raw landing 和 canonical upsert。 |
| Sync Service | `MarketDataSyncService` 负责批量同步板块目录、成分股和股票基础资料，并输出任务摘要。 |
| Capability Registry | 登记每类数据的分类、主源、fallback、目标表和是否可生成指标。 |
| Provider | `AkShareProvider`、`MootdxProvider` 只负责外部源调用和字段初步映射。 |
| Repository | 读写 Raw、Canonical、Derived 三层 `t_` 表。 |
| Config Center | `ConfigCenterService` 管理 Search、LLM、Notification 的固定配置对象、敏感值池和非敏感参数。 |
| LLM Runtime | `LlmRuntimeService` 作为内部服务调用 OpenAI-compatible 模型，并基于本地服务构建固定上下文包。 |
| Skill Runtime | `SkillRuntimeService` 作为内部服务运行项目内 Skill 资源，支持 family 级 Key 注入和 capability fallback。 |
| Scheduler Center | `SchedulerRuntime` 和 `SchedulerService` 管理任务定义、APScheduler 注册、手动触发和运行日志；具体业务任务通过 `JobHandlerRegistry` 后续逐步接入。 |
| Data Assets | `DataAssetsService` 只读巡检核心数据资产、最新日期、最近任务状态和索引缺口，支撑数据中心页面。 |
| Realtime Market | `RealtimeMarketService` 按交易日历和盘中时段维护 MooTDX 全市场 Quote、优先分钟线、板块强度和股票池实时缓存，并通过 Redis/内存与 SSE 供页面复用。 |
| Stock Pool Center | `StockPoolService` 管理系统池、自定义池和股票代码成员关系；详情只读 `t_stock`、`t_sector_basic/t_sector_component`，不触发外部 Provider。 |
| Web Admin | `web-admin` 提供 Vue3 管理后台，一级入口包含系统设置中心、数据中心、调度任务、板块中心、股票池和个股行情。 |
| Database | raw/canonical/derived 三层数据资产。 |

## 数据原则

数据库是第一优先资产。Provider 是补齐和刷新手段。所有外部响应先有 raw landing，再决定是否写入 canonical 表。

## 配置原则

Search、LLM、Notification 和 Key 统一走配置中心 v2。配置中心使用 `t_system_config` 表达固定配置对象，使用 `t_config_value` 管理 API Key、Webhook、Token、Password 等敏感值池，使用 `t_config_option` 管理非敏感参数。Skill 本体不进入配置中心，但 Skill Runtime 会复用 `search` 分类下的 family 级 Key 池。

LLM 第一版只作为内部 Python service，不暴露 `/api/v1/llm`。模型分析所需额外数据由后端调用本地服务组装为固定上下文包，模型不能主动访问本地服务或公网。

Skill Runtime 第一版也只作为内部 Python service，不暴露 `/api/v1/skills`。它负责执行旧项目迁移来的 Skill 资源和 fallback 链，不承载具体业务分析。

Scheduler Center 只实现调度底座，不承载业务逻辑。`t_scheduler_job` 保存任务定义，`t_scheduler_job_run` 保存运行日志；只有启用且配置 `cron_expr` 的任务会被 APScheduler 注册，`cron_expr=null` 表示仅手动运行。当前已由行情模块接入 `sync_sector_catalog` 和 `sync_stock_basic` 两个默认 disabled 的同步任务，策略扫描、通知发送等任务后续按模块通过 `JobHandlerRegistry` 接入。

Web Admin 当前实现系统设置中心、数据中心、调度任务、板块中心、板块资金大屏、股票池和个股行情工作台。数据中心通过 `/api/v1/data-assets/summary` 只读巡检核心表行数、最新日期/时间、最近任务状态、索引缺口和覆盖率；通过 `/api/v1/data-assets/assets/{asset_code}/gaps` 下钻个股资产缺口，区分真实缺失和当日停牌解释；通过 `/api/v1/data-assets/realtime-health` 展示实时行情缓存健康。股票池通过 `/api/v1/stock-pools` 管理四个系统池和自定义池；成员只关联 Canonical `stock_code`，详情按需读取已同步的股票资料与 Tushare 概念/行业。

## 量化数据分类

| 分类 | 代表数据 | 说明 |
| --- | --- | --- |
| 基础事实 | 股票、板块、概念、行业、指数、成分股 | 用于关联、筛选和归属，不直接等同指标。 |
| 行情事实 | 日线、分钟线、quote、盘口、分笔、板块行情、指数行情 | 用于展示、刷新和派生价格/成交量指标。 |
| 事件事实 | 龙虎榜、公告、资金流、融资融券、涨跌停池 | 先保存为可查询事实，再派生事件指标。 |
| 量化指标 | 技术指标、资金流指标、龙虎榜指标、板块强度、相对强弱 | 从 canonical 层计算，可重建，但迁移旧结果必须保留来源。 |

每日量化沉淀由三段任务组成：`daily_close_core_ingest` 负责收盘后稳定事实和基础因子，`daily_close_enrichment_ingest` 负责晚间更新较晚的增强事实和增强因子，`daily_close_repair_ingest` 负责次日滚动补缺。策略评估、市场状态、市场情绪、LLM 和 Skill 仍保持在后续独立任务中。
