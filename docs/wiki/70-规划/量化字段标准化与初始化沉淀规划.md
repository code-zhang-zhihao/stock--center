# 量化字段标准化与初始化沉淀规划
<!-- wiki-migration -->

## 背景

当前 `stock-center` 已接入 Tushare、MooTDX、AkShare 和 Skill Runtime，但不同 provider 的字段命名、日期格式、单位和含义并不一致。继续让业务服务直接处理各源字段，会导致：

- 后续更换数据源时需要到处改业务代码。
- 多源字段含义不一致，因子和回测口径容易漂移。
- 入参有时叫 `date`、有时叫 `trade_date`、有时叫 `start_date/end_date`，排查困难。
- 日志只看到 provider 原始报错，不容易定位是字段映射、单位换算、数据缺失还是外部接口异常。

因此下一轮数据底座重构必须先定义统一度量衡、统一入参、统一输出字段、统一日志和可复用映射层。

## 总体目标

固定调用链：

```text
业务数据服务 / 调度任务 / 页面聚合 API
  -> CanonicalDataService / IndicatorService
  -> ProviderAdapter（统一入参、字段映射、单位换算、质量校验）
  -> SourceClient / Transport（Tushare、AkShare、MooTDX、Skill 的具体调用）
```

业务层只理解 `stock_code/trade_date/amount_yuan/volume_shares/pct_change` 等统一字段，不直接依赖 Tushare `ts_code`、AkShare 中文列名、MooTDX 原始结构或 Skill 自然语言结果。

Provider 包内部可以继续保留 raw transport，但业务服务不能直接消费 raw transport。业务服务应调用 adapter 返回的 Canonical DTO 或者明确标记为 raw 的调试接口。

## 统一入参标准

所有内部 service、scheduler payload、页面级 API 默认使用以下字段：

| 标准字段 | 含义 | 类型 | 规则 |
| --- | --- | --- | --- |
| `stock_code` | 股票代码 | string | 无交易所后缀，如 `600519`、`002281`。 |
| `sector_code` | 板块代码 | string | 使用 canonical `t_sector_basic.sector_code`。 |
| `index_code` | 指数代码 | string | 使用 canonical `t_index_basic.index_code`。 |
| `trade_date` | 单个交易日 | date/string | API 接收 `YYYY-MM-DD`，DB 用 `DATE`，provider adapter 转为源要求格式。 |
| `start_date` / `end_date` | 日期区间 | date/string | API 接收 `YYYY-MM-DD`，闭区间。 |
| `bar_time` | 分钟线时间 | datetime | Asia/Shanghai，DB 用 timezone-aware 或明确本地时区语义。 |
| `interval` | K 线周期 | enum | `1m/5m/15m/30m/60m/1d/1w/1M`。 |
| `adjust_mode` | 复权模式 | enum | `none/qfq/hfq`，不使用 provider 私有字符串穿透到业务层。 |
| `query_mode` | 查询模式 | enum | `db_first/provider_first/db_only/provider_only/refresh`。 |
| `engine_priority` | 数据源优先级 | list[string] | `tushare/mootdx/akshare/skill` 等 provider code。 |

Provider adapter 负责转换：

- Tushare：`stock_code -> ts_code`，`YYYY-MM-DD -> YYYYMMDD`。
- AkShare：`stock_code -> symbol` 或接口要求的市场前缀。
- MooTDX：`stock_code -> market/code`。
- Skill：固定结构化参数，不让业务层传自然语言字段名。

## 统一字段与单位

### 股票行情字段

| 标准字段 | 含义 | 单位/口径 | 说明 |
| --- | --- | --- | --- |
| `open_price`、`high_price`、`low_price`、`close_price` | 开高低收 | 元 | 使用前复权/不复权由 `adjust_mode` 标记。 |
| `pre_close_price` | 昨收 | 元 | 必须保留，涨跌幅计算依赖它。 |
| `change_amount` | 涨跌额 | 元 | `close_price - pre_close_price`。 |
| `pct_change` | 涨跌幅 | 百分点 | `2.35` 表示 `2.35%`，不是 `0.0235`。 |
| `volume_shares` | 成交股数 | 股 | Tushare `vol` 为手时统一乘 100。 |
| `amount_yuan` | 成交额 | 元 | Tushare `amount` 为千元、资金流多为万元，必须统一转元。 |
| `turnover_rate` | 换手率 | 百分点 | `3.2` 表示 `3.2%`。 |
| `amplitude` | 振幅 | 百分点 | 统一由标准行情字段计算或映射。 |

### 资金流字段

| 标准字段 | 含义 | 单位/口径 |
| --- | --- | --- |
| `small_buy_amount_yuan` / `small_sell_amount_yuan` | 小单买/卖金额 | 元 |
| `medium_buy_amount_yuan` / `medium_sell_amount_yuan` | 中单买/卖金额 | 元 |
| `large_buy_amount_yuan` / `large_sell_amount_yuan` | 大单买/卖金额 | 元 |
| `super_large_buy_amount_yuan` / `super_large_sell_amount_yuan` | 超大单买/卖金额 | 元 |
| `main_net_inflow_yuan` | 主力净流入 | 元，通常为大单 + 超大单净额 |
| `main_net_ratio` | 主力净流入占成交额 | 比例，`0.032` 表示 `3.2%` |
| `fund_strength_percentile` | 资金强度横截面分位 | `0-100` |

### 因子字段

因子字段必须登记到 `t_factor_definition` 或后续统一指标字典中，至少包含：

- `factor_code`：稳定字段名，如 `ma5`、`main_net_ratio`。
- `factor_name`：中文名。
- `frequency`：`daily/minute/sector_daily/index_daily`。
- `source_tables`：依赖 canonical 表。
- `unit`：`yuan/percent_point/ratio/score/count/flag/json`。
- `calc_method`：计算口径。
- `is_recomputable`：是否可重算。
- `data_stage`：`core/enrichment/realtime/on_demand`。

字段命名约定：

- 金额统一后缀 `_yuan`。
- 数量统一后缀 `_shares`、`_count`。
- 百分点统一后缀 `_pct` 或使用明确字段名 `pct_change`。
- 比例统一后缀 `_ratio`，值域通常为 `0-1`。
- 分位/评分统一后缀 `_percentile`、`_score`。
- JSON 扩展只用于不稳定或高维指标，不能替代核心查询字段。

## Provider Adapter 边界

目录建议调整为：

```text
python-back/app/modules/market_data/
  contracts/
    query_params.py
    canonical_fields.py
    factor_fields.py
    quality.py
  providers/
    base.py
    tushare/
      transport.py
      catalog/
      adapters/
        stock_daily.py
        moneyflow.py
        sector.py
        index.py
        lhb.py
    akshare/
      client.py
      adapters/
    mootdx/
      client.py
      adapters/
    skill/
      adapters/
  repositories/
  services/
  mappers/    # 迁移期兼容，最终并入 provider adapters
```

职责划分：

- `transport/client`：只负责外部调用、鉴权、限流、错误分类，返回 raw。
- `adapter`：负责 provider raw -> canonical draft，包含字段映射、单位换算、日期转换、代码归一、质量校验。
- `service`：负责查询模式、fallback、raw/audit、canonical upsert、任务编排。
- `indicator_engine`：只读 canonical/derived，不访问 provider。

这会是一次中大型变更：目录结构、DTO、Provider 调用入口、日志和部分 repository upsert 都要调整。但数据库不需要把所有表推倒重做；优先新增指标字典和初始化 SQL 收敛，逐步修正字段单位和唯一键。

## 日志标准

所有 provider adapter 和批量任务日志必须包含：

| 字段 | 说明 |
| --- | --- |
| `trace_id/run_id` | 请求或调度运行 ID。 |
| `capability_code` | 能力编码，如 `stock_daily`、`sector_moneyflow`。 |
| `provider_code` | `tushare/akshare/mootdx/skill`。 |
| `api_name` | 外部接口名，如 `daily`、`moneyflow`。 |
| `canonical_target` | 目标表或 DTO，如 `t_daily_bar`。 |
| `request_range` | `trade_date` 或 `start_date/end_date`。 |
| `input_count` | 请求目标数量。 |
| `raw_row_count` | provider 返回行数。 |
| `mapped_count` | 成功映射行数。 |
| `upserted_count` | 入库行数。 |
| `missing_count` | 缺失数量。 |
| `unit_conversions` | 关键单位换算摘要，如 `amount: thousand_yuan -> yuan`。 |
| `warnings` | 样例化 warning，不能只写 “failed”。 |

调度任务 `result_summary` 也要保留这些摘要，便于前端运行详情直接定位慢在哪、缺在哪、错在哪。

## SQL 初始化收敛

当前 `docs/sql/` 已有 30 个演进 SQL，适合开发期追踪，但不适合作为产品部署入口。下一轮数据库整理目标：

```text
docs/sql/init.sql
docs/sql/db-init.sql
```

约定：

- `init.sql`：产品全新部署入口，创建完整 schema、表、索引、comment、基础 seed、调度任务 seed、配置对象 seed。
- `db-init.sql`：兼容部署入口，可以先执行基础扩展、schema 权限、公共函数，再调用或包含 `init.sql`；具体是否拆分由部署脚本决定。
- `docs/sql/migrations/`：保留开发期增量迁移，供旧环境升级。
- `docs/sql/archive/`：已被初始化脚本吸收的旧 SQL 可归档，只保留说明。

验收标准：

- 新环境只执行一到两个入口 SQL 即可启动产品。
- 所有字段都有 `COMMENT`。
- 所有 canonical 表唯一键符合单业务事实规则，不再按 `source` 制造重复事实。
- seed 任务中不出现已废弃任务。

## 初始化历史沉淀任务

产品部署后需要有一次性初始化任务，在非交易时段人工运行，把历史基础数据补齐；之后每日只跑增量沉淀。

### 历史任务分类

| 任务类型 | 示例任务 | 数据源 | 是否一次性 | 说明 |
| --- | --- | --- | --- | --- |
| 主数据初始化 | `sync_stock_basic`、`sync_sector_catalog`、`sync_trade_calendar` | Tushare/旧规则 | 否，后续低频运行 | 股票、板块、交易日历。 |
| 个股日频事实回填 | `backfill_stock_daily_facts` | Tushare `daily/daily_basic/moneyflow/stk_factor_pro/limit_list_d/suspend_d` | 是 | 前四个接口按股票区间回填；涨跌停/停牌按交易日全市场查询，写入 5 类事实。 |
| 个股日频因子与技术快照 | `backfill_stock_daily_factors` | 本地 canonical/derived | 是 | PostgreSQL 窗口计算 MA5/10/20/30/60、资金/专业指标和日频技术快照。 |
| 板块日频事实回填 | `backfill_sector_daily_facts` | Tushare `ths_daily/moneyflow_*_ths` | 是 | 回填板块行情和板块资金流。 |
| 板块日频因子回填 | `backfill_sector_daily_factors` | 本地 canonical/derived | 是 | 聚合板块、当前成分、个股事实和涨停事件。 |
| 指数日频事实回填 | `backfill_index_daily_facts` | Tushare `index_daily/index_dailybasic` | 是 | 按 `t_index_basic` 清单逐指数区间回填。 |
| 指数日频因子回填 | `backfill_index_daily_factors` | 本地 canonical | 是 | PostgreSQL 窗口计算 `t_index_factor_daily`。 |
| 历史分钟线与分钟因子 | 不纳入初始化 | 每日/实时链路 | 否 | 只从项目运行后逐步保留近期 20–30 个交易日，不做长历史全市场回填。 |
| 筹码胜率 `cyq_perf` | 不做批量沉淀 | Tushare `cyq_perf` | 否 | 太慢且当前价值不高，改为个股详情按需查询。 |

### 每日沉淀边界

每日任务只负责增量：

- `daily_close_core_ingest`：稳定日频事实、分钟线、基础因子。EOD quote 已废弃，盘后价格事实使用 `t_daily_bar`。
- `daily_close_enrichment_ingest`：晚到但必要的增强事实和增强因子；不再包含 `cyq_perf` 批量沉淀。
- `daily_close_repair_ingest`：最近交易日缺口修复。

`cyq_perf` 从每日增强沉淀中移除。后续如果用户打开个股行情详情页需要筹码胜率，可以通过页面级按需接口查询单只股票的多个交易日，并可选择写短 TTL 缓存或不入库。

## 数据源现状判断

当前除实时分钟线和实时 quote 候选主要依赖 MooTDX 外，历史日频事实和大部分量化指标主要由 Tushare 沉淀：

- Tushare：日线、daily_basic、资金流、涨跌停、龙虎榜、指数、板块、市场统计、专业技术因子。
- MooTDX：实时 quote 候选、当日分钟线、分时/盘口/分笔。
- AkShare：指数/板块/公告/实时排行 fallback 和补充。
- Skill：新闻、搜索、题材解释、问财/妙想语义查询，不作为核心行情事实主源。

这个方向是合理的，但必须通过统一字段和 adapter 层隔离，避免 Tushare 字段直接变成业务字段。

## 变更影响评估

| 范围 | 影响级别 | 说明 |
| --- | --- | --- |
| Provider 目录 | 大 | 需要把 raw transport、adapter、mapping 拆清楚。 |
| Service 入参 | 中到大 | 统一 `trade_date/start_date/end_date/stock_code`，需要清理不一致命名。 |
| 数据库事实表 | 中 | 不建议全部推倒，但要校验单位、唯一键、字段 comment 和指标字典。 |
| 调度任务 | 中 | 增加历史 backfill 任务，移除 `cyq_perf` 批量沉淀。 |
| 前端 | 中 | 参数表单和数据标签要使用统一字段说明。 |
| 日志 | 中 | 需要为 provider、adapter、upsert、因子阶段补标准结构化日志。 |

实施顺序建议：

1. 先落标准文档和字段字典。
2. 新增 `contracts` 与 `ProviderAdapter` 基类。
3. 先迁 Tushare 日线、daily_basic、moneyflow 三条高频链路。
4. 再迁 MooTDX quote/minute；quote 只进入实时缓存，不作为 EOD canonical。
5. 收敛 SQL 初始化入口。
6. 新增历史初始化 backfill 任务。
7. 从每日增强任务移除 `cyq_perf` 批量沉淀。

## 首批落地状态

已完成首批标准化骨架：

- `python-back/app/modules/market_data/contracts/` 定义统一查询入参、字段单位常量、`CanonicalMappingResult` 和 `ProviderAdapter` 基类。
- `python-back/app/modules/market_data/tushare/adapters/stock_daily.py` 先接管 Tushare `daily`、`daily_basic`、`moneyflow` 三条高频链路的 raw -> canonical draft 映射。
- `python-back/app/modules/market_data/tushare/adapters/market.py` 接管 Tushare `index_daily`、`index_dailybasic`、`daily_info`、`ths_daily`、`moneyflow_cnt_ths/moneyflow_ind_ths`、`top_list` 等日频/增强事实映射。
- `daily.amount` 在 adapter 中由千元转为 `amount_yuan`，`daily.vol` 由手转为 `volume_share`，`moneyflow` 金额由万元转为元；日志会输出 `unit_conversions`。
- `daily_close_core_ingest` 通过 adapter 写入日线、daily basic、个股资金流和指数日线；增强/修复任务通过 adapter 写入涨跌停/炸板与停复牌事件、板块日线、指数每日指标、市场统计、板块资金流和龙虎榜事件，并在任务日志中输出 raw 行数、映射行数、缺失数量和 warning 样例。
- `daily_close_enrichment_ingest` 与 `daily_close_repair_ingest` 已移除 `cyq_perf` 全市场批量沉淀参数和 block；`t_stock_chip_perf_daily` 仅作为历史/实验表保留。
- 历史任务已由 `docs/sql/55-data-asset-history-pipelines.sql` 收敛为个股/板块/指数各一条事实任务和一条因子任务。事实任务调用外部 Provider，因子任务只读本地 canonical/derived 表；完整顺序与并发策略见 [[历史数据资产初始化]]。
- `docs/sql/32-normalize-stock-moneyflow-yuan.sql` 将历史 `t_stock_fund_flow_daily` Tushare 资金流归一到元口径；`docs/sql/33-refresh-stock-fund-factor-ratios.sql` 用归一后的事实刷新 `t_stock_factor_daily.features` 中的资金占比字段。

## 验收标准

- 任意业务 service 里不再出现 Tushare `ts_code`、AkShare 中文列名、MooTDX 原始字段直传。
- 同一数据项在不同 provider 下输出同一 Canonical DTO。
- 金额、成交量、百分比、比例字段单位清晰，日志能打印关键换算。
- 所有调度任务入参使用统一命名。
- 历史初始化任务与每日增量任务边界清楚。
- `cyq_perf` 不再拖慢每日增强任务。
- 新部署可以通过 `init.sql/db-init.sql` 初始化完整 schema。
