## 注意

不要把策略、Skill、LLM 逻辑混入本模块；行情模块只负责事实数据查询、批量同步、raw landing、canonical upsert 和指标查询入口。

`MarketDataQueryService` 负责单次查询和 provider fallback；`MarketDataSyncService` 负责批量同步任务编排、进度摘要和异常汇总。调度中心只触发 handler，不承载行情业务逻辑。

板块中心浏览接口与统一查询接口分离：前者严格只读数据库快照，不写 raw、Canonical 或调用外部 Provider；后者保留 `query_mode` 和 `engine_priority` 的补数/刷新语义。浏览列表默认过滤 `source LIKE 'tushare:%'`，可以显式切换至 `akshare` 或 `all`。成分统计与查询始终按板块来源 family 匹配，避免同名跨源板块混入同一快照。

板块详情和资金大屏继续保持只读浏览边界。详情页行情使用 Tushare `ths_daily`，资金流历史曲线使用 `moneyflow_cnt_ths`（概念）或 `moneyflow_ind_ths`（行业），这些实时浏览请求只写运行调用日志，不写 `t_provider_raw_record` 或 canonical 表。资金大屏打开时由前端每 60 秒刷新，后端优先调用 AkShare/东财即时板块资金流，再用 Tushare `ths_hot` 补热度；它不创建调度任务，也不代表策略推荐。

个股行情工作台接口是页面级聚合层，不替代统一 `/query/*` 查询契约。`stock-analysis/{stock_code}/realtime` 先读 `RealtimeMarketService` 的内存/Redis 缓存，并在当前页面打开期间将该股票加入分钟线优先队列；交易时段发生单股缓存未命中时，会以短暂锁去重直接调用 MooTDX 的 `quote + minute` 补充实时缓存，返回 `meta.cache_status=on_demand`，不写 `t_quote_snapshot`、不写 `t_provider_raw_record`、不写 PostgreSQL。非交易时段不触发这条直拉路径。历史分钟线、日 K、资金流、事件和因子接口均只读 canonical/derived 表，不触发补数、刷新或外部 Provider 调用。历史分钟线在未指定日期时，只返回该股票有数据的最新一个交易日，避免多个交易日的相同钟点混入同一张图；数据库 UTC 时间在页面统一格式化为 `Asia/Shanghai`。分钟因子也按指定或最新的单个交易日读取完整分钟会话，固定上限 400 根，不能复用日频 `lookback` 限制，否则会错误截断为下午的 120 根；用户切换历史分钟日期时，页面同时刷新相同日期的分钟因子。实时页只在实际交易时段展示盘中缓存；非交易时段或缓存缺失时，页面自动转到日 K，并明确标识最近收盘或最后缓存，不将其伪装为实时数据。分钟图以日线 `pre_close_price` 作为昨收基准，展示分钟 MA5/MA10、昨收虚线和右侧涨跌幅轴；这两个 MA 为前端基于当前分钟序列计算，不是 Provider 虚构的均价。MooTDX 分钟返回没有均价或成交额时，页面隐藏均价和 VWAP 等不可验证曲线。日 K 与分钟成交量统一以相对前一价格的红涨绿跌显示。分钟因子的放量倍数是“当前分钟成交量 / 前 20 根有效分钟均量”，前 20 根和缺量样本明确为空，不伪造倍数；页面把它置于独立底图，并用红/橙/灰区分显著放量、略高于均量和低于均量。`intraday_strength` 使用当日截至当前的运行高低区间位置（0-1），不再与分钟收益重复。个股资金流支持近 3/5/10/20/30 个交易日窗口，展示主力净额柱、累计主力净额线和明确的净流入/净流出结论。技术指标使用中文名称、计算口径和统一单位；公告时间按 `Asia/Shanghai` 格式化。窄屏下导航会横向滚动，工作台本身保持单列且不让页面因图表或导航产生横向溢出。`stk_factor_pro` 等增强数据晚到时，接口返回已有基础因子并让前端展示“待晚间增强/修复任务补齐”。`cyq_perf` 不再作为全市场每日批量沉淀项；如果个股详情需要筹码胜率，应按单股区间按需查询。

### 实时行情 V1

`RealtimeMarketService` 只服务盘中缓存，不属于每日收盘沉淀。它按交易日历和交易时段运行：

- MooTDX `quote_batch` 每批 80 只，默认每 60 秒覆盖全市场 active 沪深股票缓存。
- MooTDX `minute(symbol)` 使用 4 个独立连接，默认每 60 秒保障 200 只；最多登记 500 只，持仓池/重点池/当前页面优先，其余强势候选轮转。
- 分钟线返回空数组时记 `no_intraday_data`，与 Provider 失败分开；目前不计算需要 `amount/avg_price` 的 VWAP 与成交额指标。
- 缓存优先 Redis，Redis 不可用时降级内存。实时缓存设 TTL 覆盖写，不在 `t_quote_snapshot/t_minute_bar` 保留高频副本。
- 数据中心通过 `GET /api/v1/data-assets/realtime-health` 展示运行状态、缓存后端、Quote 覆盖、分钟保障与错误摘要。

### 历史日频事实回填

历史事实入口收敛为 `backfill_stock_daily_facts`、`backfill_sector_daily_facts`、`backfill_index_daily_facts`。个股任务逐股对 `daily/daily_basic/moneyflow/stk_factor_pro` 各执行一次完整区间请求，并以独立 `event_workers` 按交易日调用全市场 `limit_list_d/suspend_d`，写入 `t_limit_event_daily`；事件成功日期通过 `t_provider_raw_record` 完成标记支持安全续跑。板块日 K 逐板块一次请求完整区间，默认 12 个 worker，板块资金流按已完成逐日对账的 20 个交易日窗口查询并由独立 2 个 worker 执行；指数按 `t_index_basic` 清单逐指数区间查询。三者都只写 canonical 事实，不拉历史分钟线、不计算因子、不触发策略或 LLM。

### 历史因子回填

历史因子入口收敛为 `backfill_stock_daily_factors`、`backfill_sector_daily_factors`、`backfill_index_daily_factors`。个股和指数使用 PostgreSQL 窗口函数与受控分片集合计算；板块按交易日以默认 2 个 worker 聚合。个股任务同时从日线与日频因子生成技术快照，但不读取或生成历史分钟因子。

6 个任务的完整表关系、执行顺序、并发取值和 smoke 参数见 [[历史数据资产初始化]]。

### 每日收盘数据沉淀

- 每日收盘沉淀不做策略评估、市场状态、市场情绪、Skill 或 LLM 调用，只生产可复用事实与因子。
- Canonical 分析事实采用单业务键：个股日频按 `stock_code + trade_date`，板块日频按 `sector_code + trade_date`，指数日频按 `index_code + trade_date`。`source` 只记录最终提供者，不再制造多份 canonical 事实；多源原始响应继续留在 raw/audit 层。
- `sync_tushare_a_share_topic` 与旧 `daily_market_close_ingest` 已废弃并隐藏。财务、融资融券、股东等若要补历史数据，后续单独设计 `backfill_*`，不作为每日量化沉淀入口。
- 任务先查 `t_trade_calendar`；非交易日会产生 `skipped` 运行记录。
- `sync_trade_calendar` 是交易日历主数据同步入口，沿用旧项目规则：日期为周一到周五且 `chinese_calendar.is_workday(date)` 为真时记为开市日。任务会为开市日补齐 `previous_trade_date/next_trade_date`，默认同步当前年份，也可指定年份和 `upsert/rebuild` 模式。
- 动态范围 `all_a_share` 直接读取沪深 `t_stock.status=active` 股票，不向 `t_stock_pool_member` 写入实体成员。北交所/BJ/BSE 以及 `4/8/920` 代码段股票统一为 `status=excluded`，不纳入日常量化 universe。
- `sync_index_catalog` 是指数主数据入口，和每日指数行情沉淀分离。默认同步上证综指、深证成指、创业板指、沪深300、中证500、中证1000、上证50；其中成分型指数会写入 `t_index_component`。指数成分与板块成分类似，保存当前有效关系，不按 `effective_date/source` 保留多份快照；本次完整结果中不存在的旧成分会被物理删除。任务使用 Tushare `index_basic/index_weight` 作为主源，`index_weight` 默认查询最近 3 个自然月并取最新完整 `trade_date`；AkShare `index_stock_cons` 只作为 fallback。canonical `index_code` 统一使用无后缀代码，官方 `000300.SH` 等代码保存在 metadata 中。成分型指数会校验预期成分数，fallback 去重后明显不足时跳过入库和删除，避免错误源污染当前主数据。
- `daily_close_core_ingest` 以单次全市场 `daily(trade_date)` 和 `daily_basic(trade_date)` 获取原始响应，但写入 canonical 前会按沪深 universe 过滤；返回量明显低于保护阈值即失败并交给 Scheduler 重试，不退化为逐股票外部请求。核心阶段还沉淀 `moneyflow`、`limit_list_d/suspend_d`、核心 `index_daily`、`ths_daily` 和分钟线。盘后唯一价格事实是 `t_daily_bar`，不再写 `t_quote_snapshot(snapshot_kind='eod')`。Tushare `daily/daily_basic/moneyflow/index_daily/ths_daily` 已通过 Provider Adapter 做字段映射、日期归一和单位换算。
- `daily_close_enrichment_ingest` 只沉淀晚到增强块：`stk_factor_pro` -> `t_stock_technical_factor_daily`，`top_list/top_inst` -> `t_lhb_event/t_lhb_seat_detail`，`index_dailybasic` -> `t_index_daily_basic`，`daily_info` -> `t_market_daily_stat`，`moneyflow_cnt_ths/moneyflow_ind_ths` -> `t_sector_fund_flow_daily`。增强任务不重复拉取日线和分钟线。`top_list/index_dailybasic/daily_info/moneyflow_*_ths` 已通过 Provider Adapter 输出 canonical draft。
- 增强任务采用受控并发。`stk_factor_pro`、龙虎榜、指数每日指标、市场统计和板块资金流可按 `enrichment_block_concurrency` 并发运行，每个 block 使用独立 DB session 和独立 `TushareProviderFactory`。`cyq_perf` 逐股批量沉淀耗时过长且当前量化价值有限，规划中移出每日增强任务。`result_summary.enrichment_blocks` 会记录每个 block 的耗时、行数和失败摘要。
- 增强并发不绕过 Tushare 限频。所有请求仍经过配置中心 Token 池、Token 专属 `endpoint_url`、共享 `TushareRateCoordinator`、冷却和 Scheduler timeout。单 Token 且限频较低时，理论耗时仍受官方频率约束；多 Token 或网络等待较多时，并发可提升吞吐和故障隔离。
- `daily_close_repair_ingest` 滚动修复最近 3 个交易日的增强缺口；补到哪些增强事实，就重算对应的增强因子。多日修复时，`top_list`、`index_dailybasic`、`daily_info`、`moneyflow_cnt_ths/moneyflow_ind_ths` 在第一轮按 `start_date/end_date` 区间拉取；后续交易日的运行摘要会标记这些事实为 `reused`。`top_inst` 席位明细和 `stk_factor_pro` 专业技术因子仍按单日请求。`cyq_perf` 不参与修复任务。
- 核心指数日线按单指数 fallback：先请求 Tushare `index_daily`；若目标交易日返回 0，再按目标日期请求 AkShare `stock_zh_index_daily_em`；仍失败时用 MooTDX `index` 最近 K 线过滤目标日期。任务统计只计入目标交易日实际 upsert 的行，不再用旧交易日数据凑数。
- `sync_north_hold` 默认关闭且不再作为每日完整性判断。Tushare `hk_hold` 受 2024-08-20 后北向日度披露口径影响，AkShare 个股持股接口在当前环境不稳定；如果未来要恢复，应按“季度/最近披露持股”或“北向资金流”另起事实口径。
- `cyq_chips` 明细已从业务沉淀中移除；不再有 `sync_chip_distribution` 参数，也不再保留 `t_stock_chip_distribution_daily`。`cyq_perf` 也不再作为全市场批量沉淀来源，只保留为个股按需查询候选能力。
- 增强块默认失败不拖垮核心日线沉淀，而是写入 `warnings`；若需要严格模式，可在 payload 设置 `fail_on_enrichment_error=true`。
- 全市场写库必须分块 upsert。`asyncpg` 单条 SQL 最多 32767 个绑定参数，日线、daily basic、分钟线、日/分钟因子和技术快照都会按约 1000 行或 30000 参数上限拆批，避免全市场单次沉淀生成超大 `INSERT ... VALUES`。
- 行情成交量列必须使用 `BIGINT`。早期数据库如果仍保留 `INTEGER`，需要执行 `docs/sql/17-market-volume-bigint-fix.sql`；否则即使已分批，全市场 Tushare `daily` 仍可能因单只股票成交量超过 int32 范围失败。
- 分钟线和分钟因子分区由运行时按交易日自动创建。应用账号必须是 `t_minute_bar/t_stock_factor_minute` 及其子分区 owner；如果报 `must be owner of table t_minute_bar`，需要由 `postgres` 或当前 owner 执行 `docs/sql/18-market-partition-owner-fix.sql`。任务会在 Tushare 请求前做分区 preflight，权限不满足时提前失败并提示该 SQL。
- `t_minute_bar.id` 与 `t_stock_factor_minute.id` 由 PostgreSQL identity/default 自动生成，并在 ORM 中显式标记 `autoincrement=True`。如果旧库出现 `id` 无默认生成器的 SQLAlchemy 告警，需要执行 `docs/sql/20-market-partition-identity-fix.sql`。
- 仅将当日实际取得日线的股票交给 MooTDX 同步分钟线。MooTDX 不共享同一个 socket：任务按 `minute_batch_size` 拆批，每个 worker 持有独立连接并串行拉取；每个批次完成后立即 upsert/commit，避免全市场数据攒到最后一次性写入。
- MooTDX/tdxpy 当前 intraday 类型识别只可靠覆盖沪深代码（`0/3/6` 开头）。由于当前 universe 只包含沪深 active 股票，分钟线与日频因子的目标范围保持一致。
- 第三方 `tdxpy` 在遇到不支持的证券类型时会打印 `NotImplementedError`，但这不等同于收盘任务失败。后端启动时将 `tdxpy` logger 降噪，真实 provider 失败仍以任务 `errors` 和批次摘要为准。
- `t_quote_snapshot(snapshot_kind='eod')` 已废弃为 canonical 完整性项。历史行暂不删除，但每日核心任务不再调用 MooTDX `quote_batch` 写 EOD 快照；实时行情后续走 Redis/内存缓存，不进入日频事实完整性。
- 已执行过早期收盘沉淀 SQL 的数据库，需要执行 `docs/sql/45-deprecate-eod-quote-snapshot.sql`，让调度任务参数 schema 移除 `sync_eod_quote/quote_batch_size`，并把 `t_quote_snapshot` 标记为 deprecated。
- `indicator_engine` 只读取 Canonical 表，不触发 Provider。核心阶段计算基础日频因子、资金基础因子、分钟因子和 `t_technical_indicator_snapshot`；技术快照由 `t_daily_bar + t_minute_bar + 因子表` 生成，不依赖 `t_quote_snapshot`。增强阶段融合 `stk_factor_pro/板块资金流` 后重算受影响的增强字段。
- `indicator_engine` 中的 `StockFundFactorCalculator` 读取 `t_daily_bar` 和 `t_stock_fund_flow_daily`，把主力/大单/超大单净流入成交额占比、连续主力净流入天数、近 3/5/10 日主力净流入、当日全市场资金强度横截面分位写入 `t_stock_factor_daily.features`。首批 Tushare adapter 已在写入资金流前将 `moneyflow` 金额由万元统一转为元，因此资金占比按 canonical 元/元直接计算；历史旧行通过 `docs/sql/32-normalize-stock-moneyflow-yuan.sql` 归一到元，并用 `docs/sql/33-refresh-stock-fund-factor-ratios.sql` 刷新资金占比字段。这些是基础量化因子，不是策略结论。
- `stk_factor_pro` 的完整专业技术字段保存在 `t_stock_technical_factor_daily.factors`，常用 MA/EMA/MACD/KDJ/RSI/BOLL/ATR/CCI/VR 等摘要同步到 `t_stock_factor_daily.features.tushare_technical`，不覆盖系统自算 `ma5/ma10/ma20/ma30/ma60/return_1d/amplitude/volatility_20d` 等独立列。
- 历史已沉淀的 `cyq_perf` 筹码成本和胜率可继续读取，但不再作为每日增强任务必需输入，也不再强制派生到 `t_stock_factor_daily.features.chip`。后续如个股详情需要，可通过单股区间按需查询。
- `SectorFactorCalculator` 读取 `t_sector_component/t_sector_bar/t_sector_fund_flow_daily/t_daily_bar/t_stock_fund_flow_daily/t_limit_event_daily`，生成板块近 3/5/10 日净流入、连续净流入、上涨成分数、涨停成分数、平均涨跌幅、20 日波动率、净流入成分占比、资金强度和 `放量异动/强度异动/持续流入/逆势异动` 标签，写入 `t_sector_factor_daily`。
- 因子计算只能基于 canonical 表；不得直接用 Tushare raw 或 Provider 响应计算。缺少历史窗口时照常写入可计算字段，并在 `features.missing_windows` 或 `features.fund_factor_missing_windows` 标记。
- 因子阶段必须输出可排查日志。`indicator_engine` 在计算开始、每个 batch 输入加载、batch upsert 完成、全局完成和板块因子输入加载时输出 `INFO`；日线、分钟线、资金流、专业技术因子或板块输入缺失时输出 `WARNING` 并给出少量样例代码。调度结果会把关键缺失数量同步写入 `result_summary.warnings`，前端运行记录可直接查看。
- 分钟线与分钟因子按 `trade_date` 分区。仅当分钟完整覆盖率达到 95% 时，才按 `t_trade_calendar` 清理 10 个交易日前的分区；清理失败只写入 warning，不让已完成的收盘事实沉淀整体失败。原表保留为 `*_legacy` 只读资产。

板块同步规则：

- 默认同步 `concept` 和 `industry`。
- 当前主链使用 Tushare 同花顺概念/行业与申万行业体系；AkShare 保留为显式 fallback/历史来源。
- EastMoney 板块列表失败时 fallback 到 AkShare 同花顺接口：`stock_board_concept_name_ths` / `stock_board_industry_name_ths`。
- 同花顺 fallback 的 `sector_code` 使用 `ths_concept_{code}` / `ths_industry_{code}`，避免和 EastMoney `BKxxxx` 冲突，原始 code 保留在 `metadata_json.raw_code`。
- EastMoney 成分接口通过 AkShare 分页读取，属于完整快照；完整快照中已不存在的旧关联会在同一事务内物理删除。
- 同花顺成分股适配器复用单个 Session，按前端真实分页路径逐页读取，逐页校验 `page_info`，按股票代码去重后才标记完整快照。请求全局串行并默认间隔 `0.8` 秒；单页临时失败最多重试 3 次并退避。
- 任一同花顺分页请求失败、页码/总页数不匹配、页面无有效股票或被替换为登录页时，该板块本轮整体失败，不落入部分成分，也不触发删除。公共访问可完整读取部分板块；某些深分页行业会要求登录，当前不绕过该访问控制，仍需由 EastMoney 或后续合法认证方案补齐。
- `t_sector_component` 是当前关联快照。关联 hash 相同则跳过写入；hash 不同才更新。`end_date` 是历史兼容字段，当前同步不再写入它。
- 迁移时会清空旧 `end_date` 标记，因为这些标记可能来自未完整抓取的页面，不能作为物理删除依据。
- 同花顺回退源默认 `max_concurrency=1`，`ths_request_interval_seconds=0.8`，降低请求过快触发 401/403 的概率。
- `limit_sectors`、`max_concurrency`、`provider_timeout_seconds` 可用于小范围 smoke。
- 当前环境如果访问 AkShare/EastMoney 失败，任务必须明确 failed，不能以 0 条 success 静默通过；具体 provider 异常写入 `t_scheduler_job_run.result_summary.errors`。

股票基础资料同步规则：

- Tushare 主源读取全量 A 股列表后，会在写入 `t_stock` 前做状态收口：沪深 `L/P/D` 分别为 `active/suspended/delisted`，北交所/BJ/BSE 为 `excluded`。AkShare/MooTDX fallback 只补沪深 active 列表，不能覆盖已有 `excluded/delisted/suspended`。返回数量低于 `min_expected_count` 时视为异常。
- AkShare 失败或数量异常时可 fallback 到 MooTDX。
- MooTDX fallback 只补代码、名称、交易所、状态等基础字段，不覆盖 AkShare 已有细节。
- `include_detail=true` 时渐进补充行业、上市日期、更名信息，默认每次最多 300 只。
- 不删除 `t_stock` 已有记录；Tushare `D`、AkShare 明确退市列表，以及名称匹配严格退市标记 `退市*`、`*退`、`*(退)`、`*（退）` 的沪深股票都会在每次 Upsert 前归一为 `status=delisted`。名称中间仅包含“退”不会触发该规则。
- 同步 raw 响应写入 `t_provider_raw_record`，用于排查 provider 返回内容。

## 运行配置

数据库连接沿用 `stock-analysis` 的连接池参数：`DATABASE_POOL_SIZE`、`DATABASE_MAX_OVERFLOW`、`DATABASE_POOL_TIMEOUT_SECONDS`、`DATABASE_POOL_RECYCLE_SECONDS`、`DATABASE_ECHO_POOL`。

跨域配置使用 `CORS_ALLOW_ORIGINS`，多个 origin 用英文逗号分隔。

国内行情源默认不走系统代理。后端启动时会把 `MARKET_DATA_NO_PROXY_DOMAINS` 合并到 `NO_PROXY/no_proxy`，默认包含：

```text
eastmoney.com,.eastmoney.com,10jqka.com.cn,.10jqka.com.cn,iwencai.com,.iwencai.com,sina.com.cn,.sina.com.cn,tdx.com.cn,.tdx.com.cn
```

MooTDX 不再暴露环境变量，默认在代码中使用 `market=std`、`timeout=30`、`auto_retry=3`，并从 MooTDX 自带 `HQ_HOSTS` 中按顺序尝试候选服务器。

## MooTDX 兼容策略

- quote、日线、分钟线优先通过 MooTDX `quotes` 客户端读取；某个服务器连接或调用失败时，切换到下一个 `HQ_HOSTS` 候选。
- 分笔成交通过 MooTDX `transaction/transactions` 读取，适合实时行情展示和微观结构指标。
- 指数行情 fallback 通过 MooTDX `index` 读取。
- 板块信息 fallback 通过 MooTDX `block` 读取，但 AkShare 仍是行业/概念主源。
- 股票基础资料 fallback 使用 MooTDX 股票列表能力补齐，只返回命中股票的基础字段，避免把全市场列表写入 raw。
- MooTDX 分钟线返回的是交易日内序列点，不一定携带标准时间字段；当前按 A 股连续竞价时间映射为 `09:31-11:30`、`13:01-15:00`，再规范化写入 `t_minute_bar.bar_time`。
- 外部响应写入 `t_provider_raw_record.raw_payload` 前会清理字符串中的 NUL 字符，避免 PostgreSQL JSONB 写入失败。

## TdxQuant 本地客户端 POC

`TdxQuant` 是通达信官方金融终端暴露的本地量化数据服务，和连接公共行情服务器的 `MooTDX` 不同。它需要支持 TQ 的通达信终端在数据机启动，并通过 `http://127.0.0.1:17709/` 接受 HTTP JSON 请求；当前尚未进入 `RealtimeMarketService` 的生产 Provider 链。

项目提供无副作用探测器 `python-back/scripts/probe_tdxquant.py`，用于先验证本机客户端真实能力：样本五档快照 `get_market_snapshot`、批量日 K 与单股 1 分钟 K `get_market_data`、A 股目录 `get_stock_list`、板块目录 `get_sector_list`，以及可选的批量价量接口 `get_pricevol`。探测不写 PostgreSQL、Redis 或 raw 表。

只有在盘中证明五档字段完整、200 只样本快照稳定、分钟线/证券目录字段与单位明确后，才可设计 `tdx_quant` Provider。预期分工是：Tushare 继续负责日频 canonical，TdxQuant 负责 Redis 中的实时快照和重点股票实时/分钟数据；板块实时强度仍以当前 canonical 成分关系聚合，避免混用通达信与 Tushare 的板块口径。详细运行方法见 `docs/providers/tdxquant/README.md`。

## TushareProvider

`TushareProviderFactory` 从配置中心 `market_data/tushare_pro` 解密 Token，向 `TushareTransport` 注入凭据。`.env` 不再承载 Tushare Token。Token 根据优先级、权重和最近使用时间选择；Token 与其专属 `endpoint_url` 始终成组使用；无效、权限、限频和网络故障分类记录到 `t_runtime_call_log`。

`TushareTransport` 的调用边界是 `request(TushareApiRequest)`：只做目录参数校验、Token 注入、HTTP 传输和原始 `TushareApiResponse` 返回。Provider 不负责股票代码转换、Canonical 字段映射、单位换算、raw landing 或入库；这些由 `tushare_mappers.py`、查询/同步调用方完成。A 股目录按官网股票/指数分类位于 `python-back/app/modules/market_data/tushare/catalog/`，调用契约文档由脚本生成到 `docs/providers/tushare/`。显式审计使用 `python-back/scripts/audit_tushare_a_share_catalog.py --all`，不会由配置页面自动触发。

股票关联统一使用 Canonical `t_stock.stock_code`，即 Tushare `stock_basic.symbol` 的无后缀代码，例如 `000001`。带交易所后缀的 `ts_code`（例如 `000001.SZ`）只作为 Provider 原始字段保留在 metadata/raw 中；板块成分、指数成分、行情和因子均以 `stock_code` 关联。Tushare 全市场基础资料查询使用 `exchange=""`，这是官方允许的参数值。

`sync_stock_basic` 是股票状态的唯一日常收口入口。Tushare `stock_basic.list_status=L/P/D` 映射为 `active/suspended/delisted`；其中 `suspended` 是上市状态暂停，不表示某日停牌，日度停牌仍由 `t_limit_event_daily` 表达。基础资料每次都按 `stock_code` Upsert；若沪深股票名称匹配 `退市*`、`*退`、`*(退)`、`*（退）`，即使 Provider 状态仍返回 `L`，也会在入库前归一为 `delisted`，无需额外修复 SQL。AkShare/MooTDX fallback 只补沪深 active 列表，不允许把既有 `excluded/delisted/suspended` 覆盖回 `active`。`t_stock_pool_member` 是自定义股票池成员，不是板块成分；状态同步不删除成员关系，`all_a_share` 和历史任务通过 `t_stock.status=active` 动态过滤。

共享限流按 `t_config_value.id` 在单后端进程内维护滑动窗口。每次请求先遍历所有即时可用 Token，不会因优先级最高 Token 已满额而阻塞后续 Token。交互调用最多等待 `interactive_max_wait_seconds=3`，超时返回含 `retry_at` 的可重试限频错误；调度同步使用 `scheduler_max_wait_seconds=1800` 等待最早可用配额或冷却结束，但仍受 Scheduler job timeout 限制。Tushare 上游实际限频只使 Token 进入 `cooldown_seconds`，不会标记 invalid。

每次选择 Token 时，Provider 先取该 Token 的 `endpoint_url`，为空才取 `tushare_pro.api_url` 全局默认入口。因此不同 Token 可以走不同网关或专属域名，轮换不会发生 Token 与 URL 错配。URL 配置非法或不可用时记为 `endpoint_configuration_error`，跳过当前 Token 并尝试下一条，不会误标 Token 无效。

- 查询链：基础资料、日线、同花顺概念/行业、指数、个股资金流、龙虎榜事件和公告。
- 板块详情：`ths_daily`、`moneyflow_cnt_ths`、`moneyflow_ind_ths`、`ths_hot` 作为页面只读实时/日频分析源，不在 Provider 层做入库。
- 专题任务：估值指标、复权因子、三大报表、财务指标、分红、融资融券、涨跌停、股东数据。
