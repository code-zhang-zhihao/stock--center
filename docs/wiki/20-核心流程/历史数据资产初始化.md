# 历史数据资产初始化

## 执行顺序

历史初始化固定为六个手动任务，按“个股 → 板块 → 指数”，每类内部先事实后因子：

```text
backfill_stock_daily_facts
  -> backfill_stock_daily_factors
  -> backfill_sector_daily_facts
  -> backfill_sector_daily_factors
  -> backfill_index_daily_facts
  -> backfill_index_daily_factors
```

历史分钟线和分钟因子不回填；两者由项目运行后的 15:30 每日任务积累并只保留 30 个交易日。

## 主数据前置

必须先完成：

1. `sync_stock_basic`：`t_stock`，建立沪深 active 且非 ST 范围。
2. `sync_sector_catalog`：`t_sector_basic/t_sector_component`。
3. `sync_index_catalog`：`t_index_basic/t_index_component`。
4. `sync_trade_calendar`：`t_trade_calendar`。

`pool_code=all_a_share` 是动态范围，不在股票池成员表保存全市场成员。北交所、ST 和非 active 股票不进入情绪/策略范围。

## 个股历史事实

`backfill_stock_daily_facts` 依次补齐：

| 接口 | 正式表 | 口径 |
| --- | --- | --- |
| `daily` | `t_daily_bar` | BFQ 日 K；成交量手转股，成交额千元转元。 |
| `daily_basic` | `t_stock_daily_basic` | 换手、估值、股本和市值；万股/万元统一转股/元。 |
| `adj_factor` | `t_stock_adjust_factor` | QFQ/HFQ 构造和除权校验。 |
| `moneyflow` | `t_stock_fund_flow_daily` | 万元转元；不复制价格、涨幅或排名。 |
| `stk_factor_pro` | `t_stock_factor_daily` | 78 个 QFQ 专业字段和 4 个计数直接写类型列，不保存专业 JSON。 |
| `limit_list_d/suspend_d` | `t_limit_event_daily` | 按交易日查询全市场，写涨停、跌停、炸板和停牌；零行以审计证明完成。 |

逐股区间接口对每只股票尽量只发起一次完整 `start_date/end_date` 请求。事件接口按交易日查询，避免逐股放大请求。所有外部阶段写 `t_provider_ingest_audit`，不保存响应正文。

## 个股正式因子回填

`backfill_stock_daily_factors` 只读正式窄事实和已直接写入的专业类型列：

- 默认按 20 个交易日窗口；窗口内按 `sql_stock_chunk_size=200` 分片。
- `calculation_workers` 使用 1–4 个独立数据库会话，每个股票分片独立提交。
- 额外读取约 550 个自然日预热，以覆盖最多 250 个交易日窗口。
- 组装本地收益、量额比、波动、高低点/回撤、相对沪深 300、资金累计和服务列。
- 每个日期窗口结束后只执行一次横截面分位更新，并重建对应日期的 `t_market_summary_daily`。
- `append_safe + only_missing=true` 只跳过已经满足正式计算修订的数据；部分行会继续补算。

`t_stock_factor_daily` 的 QFQ 技术核心允许本地回退，高级专业指标缺失可保持空。策略按自身 `required_inputs` 判定，不因无关的扩展指标缺失而阻塞。

## 板块历史事实与因子

`backfill_sector_daily_facts`：

- `ths_daily` 按板块代码一次查询完整历史区间，写 `t_sector_bar`。
- `moneyflow_cnt_ths/moneyflow_ind_ths` 按最多 20 个交易日窗口查询，写 `t_sector_fund_flow_daily`。
- 两个资金接口官方单位为亿元，入库统一乘 100,000,000 转元。
- `append_safe` 按业务键补缺；`rebuild` 会删除目标范围，不能用于小范围 smoke。

`backfill_sector_daily_factors` 只按 `t_sector_bar` 实际存在的交易日执行，不再对交易日历中的空日期做无效计算：

- 默认每 20 个交易日执行一次集合 SQL，同时生成板块趋势、资金累计、成分股广度、涨跌停生态和热度；每个窗口独立提交，取消后可从未完成窗口继续。
- 默认 2 个窗口 worker，运行时硬限制最多 2，避免两个大表聚合以上的并发造成数据库争用。
- 窗口内 `statement_timeout` 为 30 分钟；云库中途断开连接时该窗口自动使用新会话重试一次，查询超时不会误重试。
- `append_safe` 仍会幂等刷新目标窗口，不能仅凭“已有一行”跳过，因为旧行可能缺少最终类型列；`only_missing` 只作为旧运行参数兼容项。
- 龙头计算只处理已经生成正式板块因子的 THS 板块，每板块每天最多 5 只；不会再为全量非目标板块生成上万条无效龙头。排序阶段先按板数、涨幅和成交额选出前 5 名，再关联股票名称与因子评分，避免对全量成分逐行回表大表。
- 成分关联会应用 `start_date/end_date` 有效期。若历史目录只保存了当前快照而没有真实有效期，严格历史回测仍可能存在成分幸存者偏差，需要后续补充历史成分快照，不能由因子计算伪造。

## 指数历史事实与因子

`backfill_index_daily_facts` 对指数清单查询 `index_daily/index_dailybasic`，分别写 `t_index_bar/t_index_daily_basic`。

`backfill_index_daily_factors` 只对七大核心指数生成 `t_index_factor_daily`：MA/EMA、1/5/10/20/60 日收益、振幅、波动、高低点、回撤、量额比、趋势状态和可得估值。指数估值缺失不影响行情因子完成。

## 并发和限频

Tushare 调用频率读取配置中心 `market_data/tushare_pro.rate_limit_per_minute`，冷却读取 `cooldown_seconds`；代码默认值只在配置缺失时兜底。提高 worker 不能越过 Token 配额。

- 个股区间事实：建议 8–12 worker，按调用延迟和数据库连接池调整。
- 板块日 K：建议 12 worker；板块资金窗口独立 2 worker。
- 事件：按日期 `event_workers=4`，不受逐股 worker 影响。
- 因子：数据库计算，个股 1–4 worker；板块默认 2 个窗口 worker 且运行时最多 2。板块因子不是 Provider 请求，提高并发只会增加数据库争用。

## Smoke 与验收

| 任务 | 首次 Smoke |
| --- | --- |
| 个股事实 | `max_stocks=1`，单交易日，保留事件阶段。 |
| 个股因子 | `max_stocks=5`，单交易日。 |
| 板块事实 | 短区间，`max_sectors=5`、`workers=5`、`moneyflow_workers=1`，只用 `append_safe`。 |
| 板块因子 | 短日期区间，`factor_window_trade_days=5`、`calculation_workers=1`；任务仍只处理实际存在板块日线的日期。 |
| 指数事实/因子 | `max_indexes=1`，短日期区间。 |

扩大范围前检查任务摘要中的目标数、处理日期、失败数、写入数、覆盖率和 warning。完整验收要求个股日 K、daily basic、资金流和正式因子最新日覆盖不低于 98%，七大指数因子齐全，板块资金与亿元口径一致，事件合法零行有审计证据。

## 最终收口迁移

已有数据库从过渡资产切换为正式契约时，固定执行 `77 → 78 → 79 → 部署正式代码 → 79a → 三类历史因子回填 → 79b → 7 日观察 → 80`。`79a` 只升级历史板块因子任务的窗口参数，不改业务数据。详细门禁见 [每日事实沉淀数据字典](每日事实沉淀数据字典.md) 和 [SQL 目录说明](../../sql/README.md)。
