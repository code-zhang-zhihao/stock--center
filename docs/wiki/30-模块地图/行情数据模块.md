# 行情数据模块

## 职责

`market_data` 负责主数据、行情与事件事实、Provider 适配、接口审计、实时缓存和数据查询。`indicator_engine` 只读正式事实生成类型化派生因子。策略、LLM 和交易决策不得混入行情模块。

模块边界：

- 外部接口在 Adapter 边界完成代码、日期和单位转换。
- Canonical 表只保存不可替代事实，不保存逐行 Raw。
- `stk_factor_pro` 直接写 `t_stock_factor_daily` 类型列，不写专业 JSON 档案。
- 页面、情绪、策略和回测只读取正式表。
- Provider 完整响应只在请求生命周期内用于映射与 SHA256，正文不入库。

## 主数据

| 任务 | 正式表 | 说明 |
| --- | --- | --- |
| `sync_stock_basic` | `t_stock` | 每周 Upsert 股票名称、上市/退市状态、ST 标识；沪深 active 非 ST 构成研究范围。 |
| `sync_sector_catalog` | `t_sector_basic/t_sector_component` | 同花顺概念/行业目录和当前成分关系。 |
| `sync_index_catalog` | `t_index_basic/t_index_component` | 核心指数目录和当前成分。 |
| `sync_trade_calendar` | `t_trade_calendar` | CN 交易日范围、前后交易日和任务跳过判断。 |

主数据同步使用 insert-on-conflict-update，不要求用户手工修复已有行。退市/排除股票不再进入动态全市场和策略池，但历史事实保留。

## 每日流水线

| 任务 | Cron | 核心行为 |
| --- | --- | --- |
| `daily_close_minute_ingest` | `30 15 * * 1-5` | MooTDX 分钟线与类型化分钟因子，按 200 股分片，保留 30 个交易日。 |
| `daily_close_core_ingest` | `0 18 * * 1-5` | 日 K、daily basic、复权、个股资金流和七大指数日 K；不计算正式日频因子。 |
| `daily_close_enrichment_ingest` | `30 19 * * 1-5` | 专业技术类型列、事件、龙虎榜、板块、指数估值、北向和两融；随后生成个股/板块/指数因子和市场汇总。 |
| `daily_close_repair_ingest` | `0 8 * * 1-5` | 最近 3 个已有日 K 交易日按审计修复真实缺口，不补历史分钟线。 |

每个数据块使用独立事务。合法零事件依赖 `t_provider_ingest_audit.status=complete_zero`；网络、权限、限频或映射失败不得伪装成零行完成。

### 18:00 核心事实

- `daily` → `t_daily_bar`，唯一 BFQ 行情源。
- `daily_basic` → `t_stock_daily_basic`，万股/万元转股/元。
- `adj_factor` → `t_stock_adjust_factor`。
- `moneyflow` → `t_stock_fund_flow_daily`，万元转元。
- 七大核心指数当日优先 TickFlow 日 K，缺失指数才回退 Tushare；拒绝上一交易日数据冒充当日。
- TickFlow/Tushare 请求使用带交易所后缀的 symbol，但 `t_index_basic/t_index_bar/t_index_daily_basic/t_index_factor_daily` 统一保存无后缀六位 canonical 代码；所有库内派生与覆盖门禁必须使用 canonical 代码。

### 19:30 增强与派生

- `stk_factor_pro` 每行直接映射 78 个 QFQ 类型列和 4 个计数到 `t_stock_factor_daily`。
- `limit_list_d/suspend_d` 写涨跌停、炸板和停牌。
- `top_list/top_inst` 写龙虎榜及席位。
- `ths_daily` 按 `trade_date` 一次拉取当日全量，再本地映射到 `t_sector_bar`；不按板块代码分批，不对缺失板块做同轮空请求重试。
- `moneyflow_ind_ths/moneyflow_cnt_ths` 官方亿元金额统一乘 100,000,000 写板块资金流。
- `index_dailybasic` 允许只覆盖部分指数，不阻塞七大指数行情因子。
- `moneyflow_hsgt` 和 `margin` 是非阻塞辅助，保留实际披露日。
- 正式个股因子按 500–1000 股票分片独立提交，横截面分位单独执行一次；之后顺序生成板块因子/龙头、指数因子和市场汇总。

## 正式个股因子

`t_stock_factor_daily` 是唯一策略服务表，业务键 `stock_code + trade_date`，固定 QFQ：

- Provider 组：QFQ OHLC、MA/EMA、MACD、KDJ、RSI、BOLL、ATR 及高级技术指标。
- 本地组：收益、量额比、平均成交额、波动、高低点、回撤、相对指数、横截面分位和资金累计。
- 服务组：换手、估值、股本、市值和资金流受控副本。
- 质量组：价格、核心技术、扩展技术、估值、资金五个状态；来源、质量标记、计算修订和历史天数。

Provider 专业字段缺失时只本地回退策略核心。新股按已有历史计算短窗口，MA250 不足不影响只依赖 MA5/10/20 的策略。策略按 `required_inputs` 检查，不读取模糊全局 ready。

技术快照 API 从正式因子、BFQ 日 K 和最后一分钟因子动态生成兼容结构，不存在物理快照表。

## 历史任务

历史入口固定为：个股事实/因子、板块事实/因子、指数事实/因子六个手动任务。个股和指数使用有界日期窗口与股票分片；板块事实把日 K 与资金接口分开限流；板块和指数因子最终都写类型列。详见 [历史数据资产初始化](../20-核心流程/历史数据资产初始化.md)。

## 实时底座

外部实时能力使用 TickFlow REST，不接 WebSocket：

- 全市场 Quote：`CN_Equity_A` 每 60 秒一次，本地过滤沪深 active 非 ST。
- 决策热池：最多 200 只，Quote/五档通常 10 秒；竞价五档 5 秒。
- 温观察池：在剩余额度内轮转。
- MooTDX 分钟线：500 只可登记、优先保障 200 只，6 个连接并可压测到 8。
- 限频预算为购买额度的 90%；全市场池、按代码 Quote、五档分别使用独立令牌桶。
- Redis 租约保证只有一个实例对外请求；其他实例只读缓存并提供 API/SSE。

`/market-overview` 的市场、概念、行业和股票池聚合必须使用同一 `round_id` 的全市场 Quote。页面只读 Redis/内存缓存，不能绕过限频直接请求 Provider。涨跌停只有 Provider 返回可验证价格时统计。

实时高频 Quote/盘口不做全市场长期 PostgreSQL 沉淀；策略触发时才保存必要快照和审计证据。

## 查询与页面契约

- BFQ K 线读取 `t_daily_bar`，QFQ 技术线读取 `t_stock_factor_daily`，二者在页面展示时明确口径，不混算。
- `/stock-analysis/factors` 返回正式日频、分钟和动态快照，不返回专业 JSON、因子版本或筹码日表。
- 数据中心按分钟、个股事实、个股因子、板块、指数、市场、事件和审计展示正式资产。
- `v_stock_daily_fact` 用于普通联合查询；策略和回测直接读取正式因子。

## 数据质量和故障边界

- 核心最新日覆盖低于 95% 时 `core_ready=false`，保留上一成功缓存并列出缺失块。
- 事件接口零行必须有审计完成标记；无行且无标记是缺口。
- Tushare 单 Token 空响应可轮换其他 active Token；全部 Token 都为空后才判定真正空响应。
- THS 板块日线低覆盖时已映射行仍写入，但审计为失败并交给修复任务。
- 任何 Raw、Token 或敏感 URL 不进入业务表和审计参数。

## 最终资产迁移

正式收口使用 `77 prepare → 78 backfill → 79 cutover → 部署/重启与历史派生回填 → 79b resume → 7 日观察 → 80 cleanup`。`79` 与新应用部署之间禁止启动旧 worker；`80` 前必须确认数据库备份可恢复。
