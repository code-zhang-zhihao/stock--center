# 阶段路线图
<!-- wiki-migration -->

## 总体顺序

`stock-center` 对标 tickflow-stock-panel 的建设顺序固定为：

```text
量化字段标准化 -> 数据资产 -> 实时数据底座 -> 市场总览 -> 自选/股票池 -> 指标与选股 -> 回测 -> 监控 -> 专题分析 -> AI 与扩展数据
```

不要先堆空页面。每个页面必须能说明依赖哪些 canonical/derived 数据，缺数据时显示什么空态，以及是否触发入库。

## 第零阶段：量化字段标准化与初始化收敛

目标：

- 固定统一入参、统一字段、统一单位和 Provider Adapter 边界。
- 让业务服务只消费 canonical DTO，不直接消费 Tushare、AkShare、MooTDX 或 Skill 原始字段。
- 收敛 `docs/sql/` 的开发期增量脚本，规划产品部署入口 `init.sql/db-init.sql`。

主要任务：

- 建立 `stock_code/trade_date/start_date/end_date/interval/adjust_mode` 等统一入参标准。
- 建立金额、成交量、涨跌幅、比例、分位、评分等统一度量衡。
- 新增或扩展指标字段字典，登记 `factor_code/source_tables/unit/calc_method/data_stage`。
- 规划 `ProviderAdapter` 层：transport 只返回 raw，adapter 负责字段映射、单位换算、代码和日期归一，service 负责任务编排与入库。
- 设计标准结构化日志，输出 provider、api、raw 行数、映射行数、入库行数、缺失数、单位换算和 warning 样例。
- 规划 `docs/sql/init.sql` 和 `docs/sql/db-init.sql`，让新环境只执行一到两个入口 SQL 即可初始化。
- 将 `cyq_perf` 从全市场每日批量沉淀中移除，保留为个股详情按需查询候选能力。

验收标准：

- 业务服务不再直接使用 provider 私有字段名。
- 任一 provider 映射到同一类数据时输出相同 Canonical DTO。
- 日志能明确说明数据缺失是 provider 无返回、映射失败、单位异常还是入库失败。
- SQL 初始化入口明确，开发期历史迁移脚本可以归档。
- 每日增强任务不再被 `cyq_perf` 拖慢。

当前实现状态：

- 已落地 `market_data/contracts` 与 `ProviderAdapter` 骨架。
- Tushare `daily/daily_basic/moneyflow/index_daily/index_dailybasic/daily_info/ths_daily/moneyflow_cnt_ths/moneyflow_ind_ths/top_list` 已迁入 adapter 映射。
- 金额和成交量关键单位已收口：`daily.amount` 千元转元，`daily.vol` 手转股，`moneyflow` 万元转元。
- `cyq_perf` 已从全市场每日增强/修复任务移除，仅保留为单股按需候选能力。
- 历史事实和历史因子回填已统一 `ingest_mode=append_safe|rebuild`，默认安全补缺，必要时目标范围重建。
- `docs/sql/README.md` 已持续记录 01-36 开发期 SQL，但最终产品化 `init.sql/db-init.sql` 尚未生成。

下一步：

- 继续把 AkShare、MooTDX 和 Skill 的核心链路接入统一 adapter，避免业务层直接消费源字段。
- 生成产品部署用 `docs/sql/init.sql` 与 `docs/sql/db-init.sql`，并把开发期迁移脚本归档到 migrations/archive。
- 补齐 `t_factor_definition`/指标字典的页面或审计输出，支撑后续选股和回测。
- 对现有 service 做一次 provider 私有字段扫描，逐步消除业务层残留的 `ts_code`、中文列名和源单位换算。

## 第一阶段：数据资产与数据中心

目标：

- 建立数据资产巡检，明确每类数据是否完整。
- 补齐指数基础资料和指数成分。
- 让每日沉淀有可验收的完整性指标。

主要任务：

- 新增数据资产巡检 service/API，统计核心表行数、最新交易日、缺口和最近任务状态。
- 新增数据中心页面，展示股票、日线、分钟线、资金流、板块、指数、龙虎榜、因子和财务等资产状态。
- 执行并验证 `sync_index_catalog`，补齐 `t_index_basic`、`t_index_component`。
- 将 Tushare catalog 状态拆成 `documented/callable/persisted/used_by_page`。
- 新增部署后一次性历史初始化任务：日 K、daily_basic、资金流、指数、板块历史数据优先回填；每日收盘任务只负责增量。

验收标准：

- 数据中心能看到每类资产最新日期和完整率。
- `t_index_basic/t_index_component` 不再为空。
- 每日核心、增强、修复任务都有对应数据块完整性摘要。

当前实现状态：

- 已具备主数据和沉淀任务：`sync_trade_calendar`、`sync_stock_basic`、`sync_sector_catalog`、`sync_index_catalog`。
- 已具备每日沉淀体系：`daily_close_core_ingest`、`daily_close_enrichment_ingest`、`daily_close_repair_ingest`。
- 已具备 6 段历史初始化/补缺任务：个股、板块、指数各一条日频事实任务和一条日频因子任务；详见 [[历史数据资产初始化]]。
- 已有页面侧数据消费能力：板块中心、板块资金大屏、板块详情、股票池、个股行情工作台。
- 已新增 `sync_index_catalog` 任务代码和 SQL seed，默认同步核心指数基础资料与成分型指数成分；下一步需要执行 `docs/sql/39-index-catalog-sync-job.sql`、reload Scheduler 并手动验证 `t_index_basic/t_index_component` 不再为空。
- 已新增数据资产巡检 v2：`/api/v1/data-assets/summary` 统计 21 项核心资产的行数、最新日期/时间、最近任务运行、warning 和覆盖率；`/api/v1/data-assets/assets/{asset_code}/gaps` 支持个股资产缺口下钻；`/data-center` 页面提供资产状态表、有效完整率、缺失股票列表和调度运行概览。
- 数据中心为了避免扫大表，会检查 `trade_date/quote_time/snapshot_time` 是否有前导索引；缺索引时跳过最新日期扫描并标记“需索引”。对应索引脚本为 `docs/sql/37-data-assets-inspection-indexes.sql`，需要表 owner 或 `postgres` 执行。
- 调度运行日志和数据块日志已持续增强，能看到 raw 行数、映射行数、入库行数、warning 和 `result_summary`。

下一步：

- 将数据中心完整率继续扩展到指数清单、板块数量和 Provider catalog 状态。
- 补齐 `t_index_basic`、`t_index_component` 同步与历史回填，解决指数基础资料和成分为空的问题。
- 新增 `backfill_index_bars/backfill_index_daily_basic/backfill_sector_bars/backfill_sector_moneyflow`，补齐 Dashboard 和板块轮动所需历史。
- 将 Tushare catalog 状态拆成 `documented/callable/persisted/used_by_page`，并在数据中心或文档中展示。

## 第二阶段：实时数据底座

目标：

- 对齐 TickFlow 的实时缓存与推送能力。
- 明确实时、准实时、盘后和历史数据边界。
- 为市场总览、自选工作台、个股行情和监控中心提供统一盘中数据源。

主要任务：

- 新增 `RealtimeMarketService`，维护 quote cache、minute cache、sector realtime cache。
- MooTDX 作为实时 quote、分时、盘口、分笔主源；AkShare/东财作为板块排行和实时 fallback；Skill 不作为行情实时源。
- 全市场 quote 采用 MooTDX `quote_batch`，当前压测基线为沪深 active 股票 5210 只，`batch_size=80`，共 66 批，非交易时段一轮约 8.9 秒；`batch_size>80` 会被 MooTDX 静默截断，必须在代码中强制保护。
- 默认全市场刷新间隔为 60 秒，激进模式 30 秒；股票池/当前页面关注范围可独立 15-30 秒刷新。不规划 15 秒全市场刷新，避免请求量和聚合抖动过高。
- 实时缓存分层：`quote_cache` 存最新个股行情，`sector_member_map`/`stock_sector_map` 存板块映射，`sector_strength_cache` 存板块聚合结果，`market_breadth_cache` 存市场宽度，分钟线和盘口只做小范围短 TTL 缓存。
- 板块实时强度优先由全市场 quote cache 与 `t_sector_component` 聚合计算，不依赖外部实时板块接口；AkShare/东财只补充准实时资金流排行，Tushare 继续作为盘后事实源。
- 第一版内存预算控制在 50-150MB：不缓存全市场 raw payload、不缓存全市场逐笔、不缓存全市场五档盘口、不保存所有 quote 轮次，只保留最新快照、少量滚动窗口和聚合结果。
- 支持观察范围：核心指数、股票池、当前打开股票、板块大屏。
- 新增 SSE 或 WebSocket 推送，页面离开或隐藏时停止订阅。
- 运行日志需要记录刷新范围、provider、成功数、失败数、延迟和下一次刷新时间。

验收标准：

- 股票池和个股行情不再各自直接打 MooTDX，而是统一读实时服务。
- 全市场一轮 quote 能在默认 60 秒刷新窗口内稳定完成，返回数不能少于请求数；若出现截断、失败批次或过期数据，必须在服务状态和页面上暴露。
- 板块强度可从 quote cache + 成分股映射实时聚合出涨跌幅、上涨家数、涨停数、成交额、领涨/领跌和有效覆盖率。
- 页面明确展示“实时/准实时/盘后/历史”标签。
- 监控规则可以基于实时 cache 触发，盘后规则继续读 canonical/derived。
- 实时服务默认不高频写库，只写必要快照和触发记录。

## 第三阶段：市场总览 Dashboard

目标：

- 提供每日市场全貌，替代只看单个板块或股票。

主要任务：

- 聚合市场宽度：上涨/下跌家数、涨跌停、炸板、连板高度、成交额。
- 聚合核心指数、板块资金流、板块强度和龙虎榜事件。
- 新增市场总览页面。

验收标准：

- 最新交易日可展示市场宽度、指数、概念/行业资金排行和异动事件流。
- 不调用外部 Provider，不触发入库。

## 第四阶段：自选与股票池升级

目标：

- 将现有股票池升级为实用观察工作台，复用第二阶段的 `RealtimeMarketService`，而不是在页面内直接轮询 Provider。

主要任务：

- 建立统一观察范围抽象：`all_a_share`、`stock_pool`、`sector`、`index`，后续选股、监控和回测都按同一套范围解析。
- 股票池成员表格支持实时 quote、资金流、技术因子、板块标签。
- 股票池概览支持上涨/下跌/平盘数量、平均涨跌幅、成交额、领涨/领跌、资金流和概念/行业分布。
- 支持表格/卡片视图、列配置、排序和筛选。
- 增加行内加入监控、跳转行情、移动到其他池。
- 支持用户维护自定义主题池，例如 `PCB`、`CPO`、`半导体`、`机器人`，用于盘中观察、策略验证和监控规则范围。
- 支持从板块成分或策略结果批量写入股票池，但股票池只保存成员关系，不复制行情或因子字段。

验收标准：

- `candidate/focus/holding/breakout_retake/all_a_share` 都能作为工作台范围。
- 自定义主题池能基于实时 quote cache 展示池内实时表现。
- 页面只保存池成员，不复制行情或因子字段。

## 第五阶段：指标流水线与选股引擎

目标：

- 建立可复用的策略选股基础。

主要任务：

- 扩展 `indicator_engine`：MA/EMA/MACD/RSI/KDJ/BOLL/ATR/量比/新高新低/涨停信号。
- 建立指标字段字典，明确字段名、来源、频率、是否可重算。
- 新增策略定义模型：代码内置策略、配置化条件策略。
- 新增选股运行结果表和选股页面。
- 首批内置策略：趋势突破、均线多头、MACD 金叉放量、布林突破、量价齐升、高换手强势、连板股、断板反包、超跌反弹。

验收标准：

- 可对全市场或股票池运行策略。
- 结果可加入股票池、导出、作为监控输入。

## 第六阶段：回测引擎

目标：

- 验证策略有效性，形成研究闭环。

主要任务：

- 先实现策略回测，不先做复杂因子平台。
- 输入：策略、股票范围、日期区间、最大持仓数、手续费、滑点、止损、最大持仓天数。
- 输出：净值、回撤、夏普、胜率、交易明细。
- 后续补因子 IC/IR、分层收益、多空组合。

验收标准：

- 策略结果可直接进入回测。
- 回测结果可复现、可查看、可导出。

## 第七阶段：监控中心与通知

目标：

- 把策略和数据变成可持续观察的规则。

主要任务：

- 新增监控规则表和触发记录表。
- 支持策略结果变化、个股因子条件、价格涨跌、全市场异动四类规则；盘中规则读 `RealtimeMarketService`，盘后规则读 canonical/derived。
- 接入 Notification 配置中心，支持飞书、邮件、自定义 Webhook。
- 新增监控页面和触发记录页面。

验收标准：

- 规则可启停、可设置冷却和严重级别。
- 触发记录能说明为什么触发。
- 通知发送不泄露敏感值。

## 第八阶段：专题分析页面

目标：

- 把已沉淀数据转成交易研究视角。

主要任务：

- 连板梯队：首板、二板、三板、断板、炸板、封单/成交额和题材分布。
- 财务分析：利润表、资产负债表、现金流、财务指标趋势。
- 个股行情增强：关键价位、压力支撑、成交密集区。
- 板块分析增强：RPS 轮动、主线/新晋/退潮、成分股穿透。

验收标准：

- 专题页面只读 canonical/derived 数据。
- 缺失数据时能指出依赖哪个同步任务。

## 第九阶段：AI 与扩展数据

目标：

- 在稳定数据底座上提供报告、策略生成和扩展数据能力。

主要任务：

- AI 复盘：读取市场总览、板块轮动、涨跌停、龙虎榜和资金流生成 Markdown 报告。
- AI 策略生成：根据策略开发规范生成单个策略文件或配置化策略。
- 财务/个股 AI 解读：基于固定上下文包，不让模型直接访问外部服务。
- 扩展数据：CSV/Excel 上传、HTTP 定时拉取、JSON 写入、字段映射、股票代码归一。

验收标准：

- AI 报告可归档、可下载、可推送。
- AI 生成策略必须经过安全校验。
- 扩展数据能作为自选/选股展示列。

## 跨阶段约束

- 新功能优先复用 `t_stock.stock_code` 作为股票关联键。
- 前端页面不能直接拼底层 Provider 参数；需要页面级聚合 API。
- 调度任务只负责任务触发和运行日志，业务逻辑放在对应模块 service。
- 所有长任务必须有阶段日志、行数、错误样例和 `result_summary`。
- 不恢复已废弃的专题同步任务作为日常入口；历史补数用 `backfill_*`。
