# TickFlow 对标差距分析
<!-- wiki-migration -->

## 一句话理解

`tickflow-stock-panel` 是完整的 A 股研究工作台，核心闭环是“数据管道 -> enriched 指标 -> 选股 -> 回测 -> 监控 -> 复盘/分析”。`stock-center` 当前已经完成数据引擎、调度底座、板块/股票池/个股行情雏形，但还没有形成策略、回测、监控和复盘产品闭环。

## 对标原则

- 不引入 TickFlow 数据源，不照搬 Parquet/DuckDB 架构。
- 继续使用 PostgreSQL 的 raw/canonical/derived 三层数据体系。
- Tushare、MooTDX、AkShare、Skill 共同供数，但 canonical 分析事实保持单业务事实。
- 必须区分实时、准实时、盘后和历史数据，页面不能把盘后指标包装成实时行情。
- 第一阶段优先补数据资产、指标流水线和数据中心，再逐步补页面。
- AI 复盘、AI 策略生成、财务 AI 解读纳入长期目标，但排在数据、策略、回测和监控之后。

## 实时能力差距

TickFlow 已经具备常驻实时链路：`QuoteService` 轮询行情并维护 enriched cache，`DepthService` 拉取盘口深度，前端通过 SSE 获取 `quotes_updated`、`depth_updated`、`strategy_alert` 等事件。Dashboard、Watchlist 和 Monitor 使用同一份实时缓存，而不是每个页面临时打外部接口。

`stock-center` 当前的实时能力仍是页面级：

- 个股行情页可以临时调用 MooTDX 获取 quote、盘口和当日分时，但没有全局缓存，也没有推送。
- 板块资金大屏可以用 AkShare/东财类接口做准实时排行，但它不是统一实时服务。
- `ths_daily`、`moneyflow_cnt_ths/moneyflow_ind_ths`、日线、资金流、因子都属于日频或盘后数据，不能标记为实时。
- Skill 可以补新闻、问财语义查询和题材解释，但不能作为 quote、盘口、分时或资金排行主源。

后续必须新增 `RealtimeMarketService`：MooTDX 负责实时 quote、分钟、盘口、分笔；AkShare/东财负责准实时板块排行和 fallback；Tushare 继续负责盘后 canonical；Skill 只作为事件解释和资讯补充。

## 数据能力差距

已可作为早期产品基础的数据：

- 股票主数据、交易日历、日线、分钟线；EOD quote 已废弃，盘后价格事实以日线为准。
- `daily_basic`、个股资金流、涨跌停/停复牌、龙虎榜。
- 专业技术因子 `stk_factor_pro`、筹码胜率 `cyq_perf`。
- 板块目录、成分股、板块日线、板块资金流、板块因子。
- 核心指数日线、指数每日指标、市场交易统计。

仍需补齐的数据：

- `sync_index_catalog` 已提供指数基础和成分同步入口，仍需执行任务并验证 `t_index_basic/t_index_component` 数据覆盖。
- 财务报表、财务指标、业绩预告/快报、分红和公司行动未形成可用链路。
- 融资融券、股东户数、十大股东、增减持等专题接口未业务落库。
- 公告当前有少量数据，尚未形成公告搜索、事件归档和个股详情展示。
- TickFlow 中的第三方扩展数据能力在 `stock-center` 尚未设计。

## 优先级判断

1. 先补“数据中心 + 数据资产巡检”，让我们知道每类数据到底完整到什么程度。
2. 再补“实时数据底座”，明确哪些是盘中实时，哪些只是盘后或准实时。
3. 再补“市场总览 + 自选工作台”，利用已有数据和实时缓存形成可见价值。
4. 然后补“指标流水线 + 选股”，让数据开始服务策略。
5. 再补“回测 + 监控”，形成研究到执行观察的闭环。
6. 最后补 AI 复盘、财务 AI 和扩展数据。
