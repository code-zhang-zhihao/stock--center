## 当前边界

`web-admin` 第一版只实现系统设置中心和调度任务底座页面，不包含行情、策略、Agent、Skill、LLM 聊天调试或报表页面。

前端默认访问：

- 前端：`http://127.0.0.1:8080`
- 后端：`http://127.0.0.1:8000`

API 地址由 `VITE_API_BASE_URL` 配置，默认是 `http://127.0.0.1:8000/api/v1`。

## 启动规则

`start.sh` 默认同时启动后端和前端：

```bash
./start.sh
```

首次安装依赖并启动：

```bash
./start.sh --install
```

只启动后端时使用：

```bash
./start.sh --backend-only
```

## 页面结构

一级导航：

- `系统设置中心`：Search、LLM、Notification 三类配置。
- `调度任务`：调度任务定义、手动运行和运行日志。

系统设置中心页面使用三类 category：

- `search`
- `llm`
- `notification`

主布局：

- 左侧：domain 导航和固定配置对象列表。
- 右侧：当前配置对象详情。
- 详情页签：基本信息、业务参数、敏感值池。

默认路由直接进入 `/settings/search`，不做 landing page。旧 `/config/:domain?` 会重定向到 `/settings/:domain?`。

前端不再暴露底层通用抽象：

- 不显示 `Relations` 页签，不提供“新增 Relation”。
- 不显示“新增 Option”，只允许编辑已定义业务参数的值。
- 不显示 `node_type`、`sort_order`、`metadata` 等旧内部字段。
- 不提供新增配置对象；配置对象由 SQL/bootstrap 固定。

各 domain 的展示规则：

- `search`：只展示 `问财搜索`、`妙想搜索`、`Kimi Search` 三个配置对象，主要管理 Key 池。
- `llm`：展示 6 个模型配置对象，允许编辑模型 options、默认模型和 Key。
- `notification`：只展示 `feishu`、`email`、`webhook` 三个配置对象，只管理渠道参数，不显示敏感值池。

## API 规则

系统设置中心只调用 `/api/v1/config`：

- `GET /summary`
- `GET /items?category=search|llm|notification`
- `PATCH /items/{config_id}`
- `GET /items/{config_id}/options`
- `PUT /items/{config_id}/options`
- `GET /items/{config_id}/values`，仅 Search/LLM 页面使用
- `POST /items/{config_id}/values`，仅 Search/LLM 页面使用
- `PATCH /values/{value_id}`，仅 Search/LLM 页面使用
- `POST /values/{value_id}/disable`，仅 Search/LLM 页面使用
- `DELETE /values/{value_id}`，仅 Search/LLM 页面使用
- `POST /values/{value_id}/test`，仅 Search/LLM 页面使用

不调用旧项目的 `/providers`、`/llm`、`/notifications`、`/skills` API。
前端不调用旧 `/tree`、`/nodes`、`/relations` 接口。

调度任务页面只调用 `/api/v1/scheduler`：

- `GET /status`
- `GET /jobs?include_hidden=true|false`
- `POST /reload`
- `POST /jobs/{job_code}/pause`
- `POST /jobs/{job_code}/resume`
- `POST /jobs/{job_code}/run`
- `GET /runs`
- `GET /runs/{run_id}`

## Key 安全

- 敏感值列表只展示 `fingerprint`。
- 新增敏感值时只接收一次明文 `secret`。
- 保存后前端立即清空 `secret` 输入框。
- 编辑敏感值时可以填写新的 `secret` 来替换旧密钥；留空则不修改密钥内容。
- 敏感值可以停用，也可以删除。删除会移除 `t_config_value` 行，后续需要重新新增才能恢复。
- 敏感值测试只显示 available/error，不展示明文。
- `EM_API_KEY`、`IWENCAI_API_KEY`、`MOONSHOT_API_KEY` 不再作为表单字段暴露；前端只显示“运行时用途”。
- Notification 页面不显示敏感值池；飞书 `webhook_url`、邮箱 `smtp_password`、自定义 Webhook `webhook_url/token` 都在渠道参数中编辑。

## 验证

```bash
cd web-admin
npm run typecheck
npm run build
```

浏览器验证：

- 一级导航显示 `系统设置中心` 和 `调度任务`。
- `search` 页面只显示 Kimi Search、妙想搜索、问财搜索和 Key 管理。
- `aliyun_coding_plan` 能看到 Coding Plan options。
- `aliyun_coding_plan` 能看到迁移后的 active value。
- `volcengine_coding_plan` 当前没有 key 时显示 0。
- `notification` 页面只显示飞书、邮件、自定义 Webhook 三个配置对象。
- 页面不出现“新增 Relation”“新增 Option”“Metadata JSON”“node_type”等底层字段。
- 页面不出现 `/api/v1/llm` 或 `/api/v1/skills` 入口。
- `调度任务` 页面能看到调度状态、任务定义、运行记录，并能手动运行 `scheduler_noop`。
