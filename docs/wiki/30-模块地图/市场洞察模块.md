# 市场洞察模块
<!-- wiki-migration -->

## 定位

`market_insight` 把已沉淀的日频 canonical 事实转成可追溯、可版本化的市场情绪事实，为盘后报告、策略筛选和后续回测提供共同输入。它不调用外部 Provider、不读取盘中 Quote，也不调用 LLM。

## 输入、完成门槛与版本

评分范围固定为 `cn_a_active_non_st`：当前 `t_stock.status=active`、非 ST、交易所属于 `SH/SZ/SSE/SZSE` 的股票。每一行同时保存 `universe_code` 与 `calculation_version`；相同交易日升级算法时必须使用新的版本号，旧版本不被覆盖。

输入表为：

- `t_daily_bar`：涨跌家数、中位/平均涨跌幅和成交额。
- `t_limit_event_daily`：涨停、跌停、炸板与连续涨停高度。
- `t_trade_calendar`：连续开市日及“昨日涨停”关系。
- `t_provider_raw_record`：`limit_list_d` 已完成的 Raw 标记。

只有同时满足以下条件才写 `ready` 分数：

1. active universe 的日线覆盖率不少于 95%。
2. 当日存在 `daily_market_close_stock_limit` 或 `stock_limit_event_history_backfill` 的 `t_limit_event_daily` Raw 完成标记。

否则仍 Upsert 一行 `pending`，在 `coverage.unavailable_reasons` 记录原因，不以空事件或零值生成情绪分。

## 评分与阶段

`v1` 将可用分项按其权重重新归一化为 0–100 分；缺少“昨日涨停溢价”等非核心分项时仅移除该分项权重，原始缺失状态仍保留在 `components`。

| 分项 | 权重 | 原始值与映射 |
| --- | ---: | --- |
| 上涨扩散 | 30% | 上涨家数 ÷ active 股票数 × 100。 |
| 中位涨跌 | 20% | 中位涨跌幅在 -4% 至 +4% 线性映射为 0–100。 |
| 涨停热度 | 20% | 涨停股达到 active 股票数的 2% 时记为 100。 |
| 封板质量 | 10% | 涨停 ÷（涨停 + 炸板）× 100；分母为零时不参与加权。 |
| 昨日涨停溢价 | 12% | 昨日涨停股当日平均涨跌幅在 -5% 至 +5% 映射为 0–100。 |
| 成交活跃度 | 8% | 当日成交额相对前 5 个有效交易日均额，0.6–1.4 倍映射为 0–100。 |

阶段规则：分数不高于 25 为 `冰点期`；25–40 为 `退潮期`；40–60 为 `混沌期`；60–75 为 `修复期`；75 以上默认 `活跃期`。只有当前分数至少 75、前两次已完成分数均不低于 70、最高连板至少 3 板且昨日涨停溢价非负，才标记为 `主升期`。因此“主升期”不是单日高分的别名。

## V2 双分情绪与周期

`67-market-emotion-v2.sql` 新增 `MarketEmotionService`，但不替代 V1：`/daily-sentiment` 和 `t_market_sentiment_daily` 继续以 `v1` 兼容读取。V2 使用 `t_market_emotion_model` 管理模型、`t_market_emotion_daily` 以 `model_code + trade_date` 保存不可混淆的历史评分。草稿模型可以编辑；完成 250 个交易日基线并产生校准摘要后才可由管理员启用，启用时旧 active 模型归档，历史行不改写。

V2 始终排除 ST、北交所/BSE 和上市后的前 5 个**实际交易日**：查询按 `t_trade_calendar` 找到股票 `list_date` 后的第六个开市日，不用自然日近似，也不为这个筛选扫全量历史日 K。它只读收盘后事实，既不调用 Provider/LLM，也不把未来交易日纳入分位或周期判断。所有评分项保留原始值、单位、正/反向、前 120 个有效交易日的中位秩分位、最小历史样本数、得分、配置权重、有效权重、贡献、公式、来源和新鲜度；事件或 Provider 数据缺失时该项不可用，不会以零替代。

| 评分卡 | 维度 | 默认权重 | 代表事实 |
| --- | --- | ---: | --- |
| 短线接力情绪分 | 短线结构 | 40% | 换手自然涨停、合格跌停、炸板率、连板晋级率、连板高度/梯队。严格一字板为“收盘涨停、开盘=涨停价、`open_count=0`”；短线分只使用非一字的换手自然涨停。 |
| 短线接力情绪分 | 赚钱效应 / 题材主线 / 资金活跃 | 25% / 20% / 15% | 上涨比例、中位涨跌、宽幅涨跌比、昨日涨停溢价；V1 概念热度中的热点密度/持续性/龙头；成交额相对 5 日均值、主力资金、市场级北向流。 |
| 大盘风险偏好分 | 市场广度 / 趋势扩散 | 30% / 25% | 上涨比例、中位涨跌、宽幅涨跌比；站上 MA20/MA60、20 日新高减新低。 |
| 大盘风险偏好分 | 资金流动性 / 风险约束 | 25% / 20% | 成交额、主力资金、北向、换手/量能；核心指数趋势、指数振幅、跌停密度、20 日波动率。 |

主阶段只会返回 `冰点`、`修复`、`活跃`、`高潮`、`退潮` 之一，另显示一个辅助状态：`试错`、`发酵`、`加速`、`分歧`、`混沌轮动`或`恐慌释放`。判定优先级为“数据待完成 → 冰点 → 退潮 → 高潮 → 修复 → 活跃”；行内 `stage_evidence` 会写入命中的数值依据，例如炸板率及短线分相对 5 日高点的回落。基础事实不完整写 `pending`，滚动历史不足写 `insufficient_history`，可选指标缺失但双分仍可重归一计算时写 `degraded` 并列明缺项。

市场级 `moneyflow_hsgt` 于 21:30 增强任务落入 `t_market_north_flow_daily`，值保留 Provider 原始单位并注明来源。首次校准前，手动执行 `backfill_market_north_flow`：它只对已有 canonical 日线的最近 250 个交易日分 120 日窗口调用该区间接口，并以 `north_money` 非空作为 `append_safe` 完整条件；缺失日期会明确留在运行摘要中。`hk_hold` 与 `margin` 会对最近 5 个开市日按**实际返回的披露日**幂等补数。后两者只在 V2 页面“辅助确认”区显示最新披露日和可用汇总，`scoring_included=false`，不阻塞当日报告也不进入核心分数。

## 表与接口

`t_market_sentiment_daily` 是 Derived 表，业务唯一键为：

```text
trade_date + universe_code + calculation_version
```

字段 `metrics` 保存原始日频指标，`components` 保存评分、权重、原始值及公式，`coverage` 保存覆盖率和完成证据，`source_facts` 固定记载输入表与 universe 条件。查询接口：

```text
GET /api/v1/market-insights/daily-sentiment?trade_date=2026-07-27&calculation_version=v1
```

省略 `trade_date` 返回该版本最新行；不存在计算行时响应 `available=false, reason=market_sentiment_not_calculated`。`pending` 行也返回其覆盖信息但 `available=false`。

## 调度与历史初始化

`calculate_market_daily_sentiment` 默认在工作日 22:15 运行，依赖 21:30 的 `daily_close_enrichment_ingest`。它只读数据库，超时 900 秒，失败最多重试一次、间隔 300 秒；执行成功的结果摘要包含 ready/pending 数量和每个交易日的可审计结果。

首次建立历史阶段基线时，在调度中心手动运行该任务并同时传入 `start_date` 和 `end_date`。服务按开市日范围批量读取聚合指标、连续涨停和前置成交额，不逐股票循环；建议固定 `calculation_version=v1`。范围重跑只 Upsert 同版本同日期的 Derived 行，不改写 canonical 事实。

盘后市场复盘页调用此模块的只读 API，显示分数、阶段、覆盖率、原始关键事实与全部评分分项；昨日涨停溢价按正负值分别着色，便于快速识别溢价方向。它不提供页面内“计算”按钮，避免读页面触发写库。

## 概念热度、龙头与涨停关联证据

同一个 `calculate_market_daily_sentiment` 任务在情绪事实完成后，默认继续执行 `MarketDailyReviewService`。这不是第二个定时任务。它额外写入：

- `t_market_sector_heat_daily`：同花顺概念热度、排名、构成、龙头与覆盖证据。
- `t_market_limit_up_evidence_daily`：每只涨停股的板数、当日市场快照、热点概念归属、龙虎榜记录和已沉淀公告。

概念热度固定只聚合当前沪深 active、非 ST 成分股的以下 canonical 事实：`t_daily_bar`、`t_stock_fund_flow_daily`、`t_limit_event_daily`、`t_sector_component`。它不以 `t_sector_bar` 或 `ths_daily` 为输入，因为该接口可能在当晚晚些时候仍返回空；因此板块日 K 的发布延迟不会让报告使用上一交易日数据或虚构零值。

每个至少有 3 只有行情成分股的概念按当天横截面计算 0–100 热度，缺少资金流时移除“主力净流入”权重后重新归一化：

| 分项 | 权重 | 口径 |
| --- | ---: | --- |
| 成分股相对涨幅 | 35% | 概念成分股平均涨跌幅在当日概念中的分位。 |
| 上涨扩散 | 25% | 上涨成分股 ÷ 有行情成分股。 |
| 涨停密度 | 25% | 涨停成分股密度在当日概念中的分位。 |
| 主力净流入 | 15% | 成分股主力净流入合计在当日概念中的分位。 |

热度表保留所有符合门槛的概念；为控制夜间查询，只有热度前 24 个概念保存 3 只龙头快照。龙头排序为“是否涨停、涨跌幅、主力净流入”。盘后页默认展示前 12 个热点。

涨停证据的边界必须严格区分：

- 概念归属说明该股与当日热点概念的关联。
- 龙虎榜 `reason` 是上榜条件或交易异常说明，不是涨停原因。
- 公告只展示已经存在于 `t_announcement` 的近 3 个自然日记录；当前没有每日全市场公告/新闻完成标记，所以没有记录只能表示“未沉淀到本表”，不能表示“没有公告或新闻”。

因此当前页面统一称为“涨停关联证据”，不输出“因某新闻涨停”一类因果结论。新闻检索、证据去重和 LLM 归因属于后续解释层。

## 报告接口与调度参数

除原有情绪接口外，新增只读接口：

```text
GET /api/v1/market-insights/daily-review?trade_date=2026-07-27&calculation_version=v1&sector_limit=12&evidence_limit=40
```

| 参数 | 类型 | 必填 | 默认值 | 范围 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `trade_date` | date | 否 | 最新该版本情绪行日期 | 开市日 | 指定报告日。 |
| `calculation_version` | string | 否 | `v1` | 1–40 位字母、数字、`-`、`_`、`.` | 必须与存储版本一致。 |
| `sector_limit` | int | 否 | 12 | 1–50 | 返回的热点概念数量。 |
| `evidence_limit` | int | 否 | 40 | 1–200 | 返回的涨停关联证据数量。 |

返回的 `available=false` 表示情绪、概念热度或涨停证据尚未齐全；`coverage` 同时给出已写入和预期涨停证据行数。读接口不会触发计算或外部请求。

调度表单新增 `include_report_facts`（boolean，默认 `true`）。日常运行保持开启；只需要大范围回填历史**情绪基线**时可关闭它，避免同时计算大量概念/证据快照。历史报告事实如需回填，应按可控日期范围分段执行并保留同一 `calculation_version`。

V2 只读查询与模型接口如下：

```text
GET  /api/v1/market-insights/emotion-daily?trade_date=2026-07-27&model_code=cn_a_emotion_v2&history_limit=250
GET  /api/v1/market-insights/emotion-models
GET  /api/v1/market-insights/emotion-models/{model_code}
POST /api/v1/market-insights/emotion-models
PATCH /api/v1/market-insights/emotion-models/{model_code}
POST /api/v1/market-insights/emotion-models/{model_code}/calibrate
POST /api/v1/market-insights/emotion-models/{model_code}/activate
```

`emotion-daily` 无 active 模型时返回 `available=false, reason=market_emotion_model_not_active`；模型已启用但尚未计算时返回 `market_emotion_not_calculated`。`history_limit` 是返回 `trend` 的交易日数量，默认 `60`、范围 `20–1000`；盘后页保持默认，情绪模型页按模型的基线长度请求完整校准曲线。模型创建只生成草稿；`PATCH` 只接受草稿的名称、窗口、基线和完整 `parameter_json`。`calibrate` 先将模型标记为 `calibrating`，返回同一 22:15 handler 的手动任务 payload（`emotion_mode=baseline`）；后台只读取本地事实，基线前置窗口精确为 120 个开市日，不再按 620 个自然日扩大扫描范围。首次检查点中的首尾交易日会转换为 ISO 日期字符串后写入 JSONB，不能因 Python `date` 序列化失败而在加载输入前中止。八个输入块会把当前块、耗时和日期规模写入运行摘要；其中“20 日创新高/新低”按 20 个交易日执行有界索引查询并报告子批次。评分每 20 个交易日 Upsert 并提交检查点，因此超时后可从已写入事实安全重跑。完成后写入阶段分布和分数范围。日常运行复用已持久化的 V2 原始指标历史，只读取有限的近期结构上下文，不再为单日评分重复扫描整段基线。`activate` 只接受 `ready + baseline_complete` 模型。

盘后页以 `emotion-daily` 为优先双分区，展示双分、阶段/辅助状态、评分卡与每项审计字段；V2 尚不可用时 V1 区仍正常显示。`/emotion-models` 页面可克隆模型、编辑两张评分卡权重和阶段阈值、启动校准并由管理员确认启用；完成校准后会展示完整基线的“短线接力 / 大盘风险偏好”双线、可缩放时间轴、按连续交易日合并的五阶段时间带，以及 `degraded` 日数量提示。曲线是评分结果的校准审阅，不是未来收益曲线。校准摘要同时展示样本内 T+1/T+3 的后续市场广度、平均核心指数变化，以及高/低短线分分组的后续广度。该验证只在评分完成后读取后续已沉淀事实，绝不回灌到任一历史日的分位、分数或阶段。页面不直接触发 Provider。

`66-market-daily-review-facts.sql` 同时修复旧收盘任务的质量语义：当 `ths_daily` 对已有 THS 目标板块返回 0 行时，Raw 审计记录保留但状态为 `failed`（错误码 `ths_daily_empty_or_not_published`），增强块显示 `deferred` 并交给次日缺口修复，不再以 `captured` 冒充板块日 K 已完成。

## 回归验证

`tests/test_market_daily_review_service.py` 覆盖概念热度排序、相同输入的并列分位、市场事实未完成时不评分、连板在缺失事件完成标记后重置，以及失效概念成分不会进入涨停关联证据。`tests/test_daily_close_pipeline.py` 覆盖 `ths_daily` 空响应审计为带专用错误码的 `failed`。这些测试不依赖 Provider、LLM 或数据库写入；实际 PostgreSQL 只读探针可验证当日概念聚合、龙头候选、涨停和成分关系查询。
