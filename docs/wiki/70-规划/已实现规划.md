## 当前主线

当前建设顺序仍是：

```text
量化字段标准化 -> 数据资产 -> 实时数据底座 -> 市场总览 -> 自选/股票池 -> 指标与选股 -> 回测 -> 监控 -> 专题分析 -> AI 与扩展数据
```

已完成的核心方向：

- 数据库统一使用 `t_` 前缀，保留 Raw / Canonical / Derived 三层思路。
- Canonical 分析事实采用单业务事实，不再按 `source` 制造多份事实；`source` 只记录最终来源。
- 股票关联键统一使用无后缀 `stock_code`。
- 北交所/BJ/BSE 统一为 `excluded`，不进入沪深 active universe；名称以 `退市` 开头的沪深股票归为 `delisted`，不进入每日沉淀范围。
- Tushare 作为日频事实主源，MooTDX 作为分钟线和未来实时 quote 候选源，AkShare 作为 fallback/准实时补充，Skill 不作为核心行情事实主源。`t_quote_snapshot(snapshot_kind='eod')` 已废弃，盘后价格事实只认 `t_daily_bar`。
- 历史事实和历史因子回填统一支持 `ingest_mode=append_safe|rebuild`：默认安全补缺，必要时目标范围重建。

## 历史因子是否可以回填

可以，并且已落地个股日频因子、技术快照和板块日频因子回填任务。它们作为独立手动任务存在，不混入每日核心/增强/修复任务。

已实现任务：

```text
backfill_daily_factors
backfill_technical_snapshots
backfill_sector_factors
```

仍未实现、后续按需再做：

```text
backfill_minute_factors
```

核心原则：

- 只读 canonical/derived 依赖表，不调用 Tushare、MooTDX、AkShare 或 Skill。
- 输入为 `start_date/end_date`、`pool_code`、`ingest_mode`、`max_stocks`、`factor_window_trade_days`、`sql_stock_chunk_size` 等运维参数。
- `backfill_daily_factors` 先按 `t_trade_calendar` 展开交易日，再按连续交易日窗口由 PostgreSQL 窗口函数和 `INSERT ... SELECT` 计算；每个窗口按默认 200 只股票独立提交，避免单条全市场 SQL 占用过多云端数据库内存，并支持 append-safe 安全续跑。
- 股票日频因子依赖 `t_daily_bar`、`t_stock_fund_flow_daily`、可选 `t_stock_technical_factor_daily`。
- 分钟因子依赖 `t_minute_bar`，只建议回填最近 10 个交易日或指定股票池，不建议全市场长历史。
- 技术快照现在由 `t_daily_bar + t_minute_bar + 因子表` 生成，不再依赖 `t_quote_snapshot(snapshot_kind='eod')`。没有分钟线时仍可生成价格、涨跌幅和趋势类字段，量能/盘中强度会部分为空。
- 板块因子依赖 `t_sector_component/t_sector_bar/t_sector_fund_flow_daily/t_daily_bar/t_stock_fund_flow_daily/t_limit_event_daily`。
- 缺依赖时写 warning 和 result_summary，不触发外部补数。
