## 当前边界

`web-admin` 当前实现系统设置中心、数据中心、调度任务、板块中心、板块资金大屏、股票池和个股行情工作台。股票详情以股票池详情弹窗提供；`all_a_share` 在股票池中展示为只读动态范围，成员实时来自已同步的 `t_stock.status=active`，页面不会显示手工添加或移除入口。个股行情工作台只展示行情事实、资金流、因子和事件，不包含交易、策略推荐、Agent、Skill、LLM 聊天调试或报表页面。

前端默认访问：

- 前端：`http://127.0.0.1:8080`
- 后端：`http://127.0.0.1:8000`

API 地址由 `VITE_API_BASE_URL` 配置，默认是 `http://127.0.0.1:8000/api/v1`。

## 启动规则

`start.sh` 默认同时启动后端和前端：

```bash
./start.sh
```

首次安装依赖并启动：

```bash
./start.sh --install
```

只启动后端时使用：

```bash
./start.sh --backend-only
```

当 `SCHEDULER_ENABLED=true` 但数据库暂时不可连时，后端仍会启动，调度任务页面会在状态区显示 `/api/v1/scheduler/status.error`。数据库连通性以 `/api/v1/health/db` 为准，不以 `/api/v1/health` 判断。

## 页面结构

一级导航：

- `系统设置中心`：Search、LLM、Notification 和数据源配置。
- `数据中心`：核心数据资产巡检、最近任务运行和索引缺口。
- `调度任务`：调度任务定义、手动运行和运行日志。
- `板块中心`：浏览已同步的概念/行业板块及其成分股。
- `股票池`：管理四个系统池、自定义池和股票代码成员关系。
- `个股行情`：查看单只股票的实时 quote/分时、历史分钟线、日 K、资金流、技术/筹码因子和事件。

系统设置中心页面使用四类 category：

- `search`
- `llm`
- `notification`
- `market_data`

主布局：

- 左侧：domain 导航和固定配置对象列表。
- 右侧：当前配置对象详情。
- 详情页签：基本信息、业务参数、敏感值池。

默认路由直接进入 `/settings/search`，不做 landing page。旧 `/config/:domain?` 会重定向到 `/settings/:domain?`。

前端不再暴露底层通用抽象：

- 不显示 `Relations` 页签，不提供“新增 Relation”。
- 不显示“新增 Option”，只允许编辑已定义业务参数的值。
- 不显示 `node_type`、`sort_order`、`metadata` 等旧内部字段。
- 不提供新增配置对象；配置对象由 SQL/bootstrap 固定。

各 domain 的展示规则：

- `search`：只展示 `问财搜索`、`妙想搜索`、`Kimi Search` 三个配置对象，主要管理 Key 池。
- `llm`：展示 6 个模型配置对象，允许编辑模型 options、默认模型和 Key。
- `notification`：只展示 `feishu`、`email`、`webhook` 三个配置对象，只管理渠道参数，不显示敏感值池。
- `market_data`：展示 `Tushare Pro` 和 `Redis Cache`。Tushare 管理 Token 池与数据源参数；Redis 管理加密 `redis_url` 敏感值、缓存后端、Key 前缀、超时和数据中心缓存 TTL。

## API 规则

系统设置中心只调用 `/api/v1/config`：

- `GET /summary`
- `GET /items?category=search|llm|notification|market_data`
- `PATCH /items/{config_id}`
- `GET /items/{config_id}/options`
- `PUT /items/{config_id}/options`
- `GET /items/{config_id}/values`，Search/LLM/数据源页面使用
- `POST /items/{config_id}/values`，Search/LLM/数据源页面使用
- `PATCH /values/{value_id}`，Search/LLM/数据源页面使用
- `POST /values/{value_id}/disable`，Search/LLM/数据源页面使用
- `DELETE /values/{value_id}`，Search/LLM/数据源页面使用
- `POST /values/{value_id}/test`，Search/LLM/数据源页面使用

不调用旧项目的 `/providers`、`/llm`、`/notifications`、`/skills` API。
前端不调用旧 `/tree`、`/nodes`、`/relations` 接口。

调度任务页面只调用 `/api/v1/scheduler`：

- `GET /status`
- `GET /jobs?include_hidden=true|false`
- `POST /reload`
- `POST /jobs/{job_code}/pause`
- `POST /jobs/{job_code}/resume`
- `POST /jobs/{job_code}/run`
- `PATCH /jobs/{job_code}`
- `GET /runs`
- `GET /runs/{run_id}`

数据中心页面只调用 `/api/v1/data-assets`：

- `GET /summary`
- `GET /daily-health`
- `GET /cache-status`
- `POST /refresh`
- `GET /assets/{asset_code}/gaps`

数据中心 v2 展示主数据、日频事实、分钟/快照和 Derived 四类资产。接口统计行数、最新交易日/时间、最新日期行数、最近调度运行、warnings 和覆盖率。主数据包含 `t_stock`、`t_trade_calendar`、`t_sector_basic/t_sector_component`、`t_index_basic/t_index_component`；其中板块和指数成分都按当前有效关系维护，只展示业务计数和关系覆盖，不要求 `updated_at/created_at` 时间索引。日频事实按 `trade_date` 巡检，快照类按业务时间巡检。巡检索引脚本为 `docs/sql/37-data-assets-inspection-indexes.sql`。

数据中心健康度使用可选缓存层：运行时优先读取“系统设置中心 > 数据源 > Redis Cache”的加密 `redis_url` 和缓存参数；配置中心未启用或未配置 Redis 时回退 `.env` 的 `REDIS_URL/CACHE_BACKEND/REDIS_KEY_PREFIX/DATA_ASSET_CACHE_*`；Redis 不可用或 `CACHE_BACKEND=memory` 时自动降级为后端进程内本地缓存。页面首屏读取 `/summary` 和 `/daily-health` 时优先使用缓存。手动点击“刷新缓存”会调用 `POST /refresh?snapshot_key=all&async=true` 提交后台刷新，浏览器请求立即返回，后台使用独立 DB session 重新生成资产总览和交易日完整性缓存，避免一次全库巡检被 30 秒 HTTP 超时打断。缓存状态通过 `/cache-status` 展示，页面提交后会延迟重读缓存。后台预热任务为 `refresh_data_asset_health`，由 `docs/sql/42-data-asset-health-cache.sql` seed；Redis Cache 配置对象由 `docs/sql/43-redis-cache-data-source.sql` seed。

Redis Cache 的 TTL 不再只有一个总开关。`data_asset_cache_ttl_seconds` 是数据中心缓存默认 TTL；`data_asset_summary_ttl_seconds` 控制数据资产总览缓存；`data_asset_daily_health_ttl_seconds` 控制最近交易日完整性缓存；`default_cache_ttl_seconds` 预留给后续实时行情等其他缓存族。当前只为数据中心配置专属 TTL，实时行情类缓存后续在实时数据底座阶段再规划。

`GET /daily-health` 返回最近交易日完整性矩阵，默认最近 3 个交易日，覆盖日线、daily basic、个股资金流、专业技术因子、分钟线、日频因子、分钟因子和技术快照。`t_quote_snapshot(snapshot_kind='eod')` 已废弃为日频完整性项：盘后唯一价格事实是 `t_daily_bar`，技术快照不再依赖 EOD quote。前端在资产表上方展示每个交易日的有效完整率、真实缺失和停牌/无交易解释数，用于快速区分“任务没跑/数据真缺”和“股票停牌导致没有市场记录”。分钟线和分钟因子按分区行数除以 240 估算覆盖股票数，避免数据中心首屏为了巡检扫百万级分钟明细。

对个股日频/分钟/快照/Derived 资产，数据中心按沪深 `active` universe 计算覆盖率：`expected_count` 为当前 active 股票数，`actual_count` 为目标表指定日期已有股票数，`exempt_count` 为可解释缺口，`missing_count` 为真实缺失。可解释缺口包含两类：一是 `t_limit_event_daily.event_type='suspend'` 的显式停牌；二是同一交易日 `t_daily_bar/t_stock_daily_basic/t_stock_fund_flow_daily` 均无记录的“无日频市场记录，疑似停牌/无交易”。页面显示有效完整率，并可通过“查看缺口”打开下钻列表，直接看到缺失股票、交易所、状态和原因。

板块中心只调用数据库浏览 API：

- `GET /api/v1/market-data/browse/sectors`
- `GET /api/v1/market-data/browse/sectors/{sector_code}/stocks`

页面默认展示 Tushare 同花顺概念/行业快照，可以切换 AkShare 历史来源或全部来源；列表和所选板块会写入 `/sectors` URL 查询参数。页面不提供外部刷新、行情或 K 线操作，数据更新仍通过调度任务完成。

板块目录和成分股均固定每页 20 条：左侧目录在独立滚动区内浏览并固定页码；右侧按“标题、筛选、可滚动表格、固定页脚”布局，表格滚动不会挤走分页或同步时间。页脚会展示当前范围，例如 `显示 1-20 / 60，每页 20 条`。

板块资金大屏位于 `/sector-dashboard`，与板块中心同级。页面调用 `GET /api/v1/market-data/sector-analysis/dashboard`，展示即时资金流、涨跌幅、热度、领涨股和成分数量；默认每 60 秒刷新一次，离开页面或关闭开关后停止刷新。该页面只消费只读接口，不触发调度任务和数据入库。

板块详情页位于 `/sectors/:sectorCode`，可以从板块中心每行“详情”进入，也可以在详情页顶部按板块名称或代码搜索切换。页面调用 `sector-analysis` 只读接口展示 `ths_daily` 行情线、`moneyflow_cnt_ths` 资金流柱线、领涨股列表和成分股分页；图表为轻量 SVG，第一版不引入 ECharts。

调度任务详情支持可视化编辑：仅手动、每天、每周、每月 1-28 日和自定义 Cron；页面展示最终 Cron 预览，并将排期、启停、单次尝试超时、重试策略和默认参数通过 `PATCH /jobs/{job_code}` 保存。默认参数与手动运行都由 `parameter_schema` 渲染字段表单，包含参数含义、选项、范围和 JSON 校验；内部 identity、handler 类型、schema、metadata 和并发运行时字段不在常规界面暴露。

股票池页面使用同样的主从布局：左侧池目录独立滚动，右侧成员表固定每页 20 条。系统池 `candidate/focus/holding/breakout_retake` 只允许启停和成员管理；自定义池可按用户填写的 `pool_code` 创建、编辑和删除。添加成员使用 `GET /api/v1/stock-pools/{pool_code}/candidate-stocks` 搜索本地 `t_stock` 的正常交易股票，按代码或名称匹配，最多返回 20 条；结果会标记当前池已有成员，前端支持多选后复用批量写入接口。该查询不触发 Provider。详情弹窗才查询股票基础资料和 Tushare 概念/行业；“查看行情”跳到 `/market?stock_code=...` 个股行情工作台。

个股行情工作台位于 `/market?stock_code=600519`。页面顶部支持股票代码/名称搜索、手动刷新和实时自动刷新开关；股票非 `active` 时默认关闭实时刷新。主图表区包含实时分时、历史分钟和日 K，图表使用 `echarts` 和 `MarketChart.vue` 统一渲染；日 K 默认取 250 个交易日，MA5/10/20/30/60 直接使用同一接口每条 K 线附带的同日字段，不再与只取 120 天的因子详情响应拼接。实时分时调用只读展示接口，默认 30 秒刷新且只在当前页签启用。右侧展示基础资料、估值/换手、技术快照和所属板块；下方展示资金流、系统自算 MA5/10/20/30/60 等技术因子、Tushare 专业技术因子摘要、筹码胜率摘要、分钟因子、龙虎榜/涨跌停/公告。页面不会触发沉淀任务、补数或 Provider raw landing。

前端以 `StockDailyChartBar` 表示附带五条 MA 的日 K 页面响应，与只表示行情事实的 `StockDailyBar` 分开，避免概览接口被误认为必须携带因子列。

## Key 安全

- 敏感值列表只展示 `fingerprint`。
- 新增敏感值时只接收一次明文 `secret`。
- 保存后前端立即清空 `secret` 输入框。
- 编辑敏感值时可以填写新的 `secret` 来替换旧密钥；留空则不修改密钥内容。
- 敏感值可以停用，也可以删除。删除会移除 `t_config_value` 行，后续需要重新新增才能恢复。
- 敏感值测试只显示 available/error，不展示明文。
- `EM_API_KEY`、`IWENCAI_API_KEY`、`MOONSHOT_API_KEY` 不再作为表单字段暴露；前端只显示“运行时用途”。
- Notification 页面不显示敏感值池；飞书 `webhook_url`、邮箱 `smtp_password`、自定义 Webhook `webhook_url/token` 都在渠道参数中编辑。

## 验证

```bash
cd web-admin
npm run typecheck
npm run build
```

浏览器验证：

- 一级导航显示 `系统设置中心` 和 `调度任务`。
- `数据中心` 页面能加载资产状态；主数据不会因为缺少更新时间索引而出现 warning，日频事实以最新交易日作为新鲜度判断。
- `search` 页面只显示 Kimi Search、妙想搜索、问财搜索和 Key 管理。
- `aliyun_coding_plan` 能看到 Coding Plan options。
- `aliyun_coding_plan` 能看到迁移后的 active value。
- `volcengine_coding_plan` 当前没有 key 时显示 0。
- `notification` 页面只显示飞书、邮件、自定义 Webhook 三个配置对象。
- 页面不出现“新增 Relation”“新增 Option”“Metadata JSON”“node_type”等底层字段。
- 页面不出现 `/api/v1/llm` 或 `/api/v1/skills` 入口。
- `调度任务` 页面能看到调度状态、任务定义、运行记录，并能手动运行 `scheduler_noop`。
